Linux Privilege Escalation

Privilege Escalation is the process of gaining higher privileges on a system than those originally assigned to a user.

In penetration testing, it is often performed after obtaining initial access to a machine.

Why Is Privilege Escalation Important?

Many compromised accounts have limited permissions.

Privilege escalation allows an attacker to gain administrative or root access.

Types of Privilege Escalation

Vertical Privilege Escalation

Gaining higher privileges than the current user.

user → root
Horizontal Privilege Escalation

Accessing resources belonging to another user with similar privileges.

user1 → user2

Initial Enumeration

Enumeration is the most important step in privilege escalation.

Always gather as much information as possible.

Current User
whoami
User Information
id
Hostname
hostname
Operating System
uname -a
cat /etc/os-release

Sudo Privileges

Check whether the user can execute commands with sudo.

sudo -l

Example:

(ALL) NOPASSWD: /usr/bin/vim

This may allow privilege escalation.

SUID Binaries

SUID files execute with the permissions of their owner.

If owned by root, they may provide a path to root access.

Find SUID files:

find / -perm -4000 2>/dev/null

Example:

-rwsr-xr-x root root /usr/bin/passwd

SGID Binaries

SGID files execute with group permissions.

Find SGID files:

find / -perm -2000 2>/dev/null

Writable Files and Directories

Misconfigured permissions may allow privilege escalation.

Find writable directories:

find / -writable 2>/dev/null

Scheduled Tasks (Cron Jobs)

Cron jobs execute commands automatically.

Misconfigured jobs may allow attackers to execute code as root.

View scheduled tasks:

crontab -l
cat /etc/crontab

Running Processes

Identify services running as root.

ps aux

Environment Variables

Misconfigured environment variables can sometimes be abused.

env

Password and Configuration Files

Look for sensitive files containing credentials.

/etc/passwd
/etc/shadow
config.php
.env

Kernel Exploits

Outdated kernels may contain local privilege escalation vulnerabilities.

Check kernel version:

uname -r

Always verify exploit compatibility before testing.

PATH Hijacking

Applications sometimes execute commands without specifying full paths.

This may allow attackers to execute malicious binaries.

Check PATH:

echo $PATH

NFS Misconfigurations

Improper NFS exports may allow unauthorized file access or privilege escalation.

Check exports:

cat /etc/exports

Capabilities

Linux capabilities grant specific privileges without full root access.

List capabilities:

getcap -r / 2>/dev/null

Automated Enumeration Tools

Common tools used during privilege escalation:

• LinPEAS

• LinEnum

• Linux Smart Enumeration (LSE)

• pspy

Privilege Escalation Workflow

1- Identify the current user.

2- Enumerate the system.

3- Check sudo permissions.

4- Search for SUID and SGID binaries.

5- Look for writable files and directories.

6- Inspect cron jobs.

7- Check capabilities.

8- Review running services.

9- Search for credentials.

10- Evaluate possible escalation paths.

Common Commands

id
sudo -l

env

What Should a Penetration Tester Check?

• Sudo misconfigurations

• SUID binaries

• SGID binaries

• Writable files

• Writable directories

• Cron jobs

• PATH hijacking opportunities

• Exposed credentials

• Linux capabilities

• Kernel vulnerabilities

Important Note

Successful privilege escalation is usually the result of thorough enumeration.

Most privilege escalation opportunities are discovered during information gathering rather than exploitation.
