SSH Attack Detector

You can carry out this task practically in an isolated lab if you do not have a lab you can set one up using this link.

In this task, we will carry out an attack to generate logs within the authentication files for later analysis.

The `ip a` command is used to identify the victim machine's address; this is the most crucial step, as we will need to access the machine using this address later. The results show the IP address as 192.168.150.129.

The command `sudo systemctl status ssh` is used to check the status of the SSH service and the results indicate that it is running.

We now have the necessary information the IP address and have confirmed that the SSH service is running.

Here we begin executing the attack with the aim of generating records.

We used the command `ssh admin@192.168.150.129` to access the victim's machine however before completing the attempt we need to terminate the connection because we want to generate a specific type of log entry.

Also we tried logging in using a non-existent user such as "admin" as this will generate a different type of log entry.

We also attempted to log in using the user `barakuser@192.168.150.129` but this time we will let the login attempt proceed as we also want to generate a different type of log entry. In these steps we carried out a manual attack

We want to generate a large number of failed login attempts so we will use Hydra this time We will use the command `nano passwords.txt` to create the password file.

Enter these words you can type whatever then Enter the correct user password since we want a successful login this time and place it on the last line. 1234 123abc, abcd, 1111, 2222, 3333, 4444, Press Ctrl+O to save then Enter and finally Ctrl+X to exit.

'hydra -l IT-support -P passwords.txt ssh://192.168.150.129'

We used the command to execute a brute-force attack.

As you can see, Hydra successfully logged in using the IT-support user account.

We will stop here we have generated enough records.

We begin analyzing the records from this step.

We used the command `sudo grep "Failed password for root" /var/log/auth.log` to check for root login attempts but the results showed that there were no such attempts.

The results also indicated that there were no successful logins via root.

sudo grep -E "Failed password"|Accepted password" /var/log/auth.log

The results indicate an attempted login by a non-existent user. The account is admin.

There are also failed login attempts using the user 'barakuser'.

There were also failed login attempts using the user "barakuser" and the user "IT-support" but eventually a successful login was achieved using that same user account.
