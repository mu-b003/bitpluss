Suspicious Connections Analysis

You can carry out this task practically in an isolated virtual lab if you do not have a lab you can set one up using this .link

Commands: sudo apt updateThen sudo apt upgradeon the Ubuntu machine (soc-lab), to update the system before starting the exercise. Result: One upgradeable package was detected, but it was not upgraded due to the "phasing" mechanism of snapd — Summary: 0 upgrades, 0 installations, 0 removals, 1 unupgraded.

Commands: sudo apt install apache2Then, sudo apt install openssh-serveron Ubuntu, to check if the two target services are installed. Result: Both packages are pre-installed with the latest version (Apache 2.4.66-2ubuntu2.4 and OpenSSH 1 : 10.2p1-2ubuntu3.5), no installation is required.

Commands: sudo systemctl start apache2 Then sudo systemctl status apache2to confirm that the web service is running. Result: The service has been active (running) for 2 days (July 19, 2:28 PM ), with a recent reload history dated July 21, 5:53 PM .

Commands: sudo systemctl start ssh Then sudo systemctl status sshto verify that the SSH service is running. Result: The service has been active for only one hour (started 17:59:32 ) , with multiple warning logs documenting failed connection attempts from the address 192.168.81.128due to protocol version differences and key exchange algorithm incompatibility — an indication of a previous scan or attack on the service.

Commands: ip a On Ubuntu, to check network settings. Result: ens33Active interface with dynamic IP address 192.168.81.129/24, ready to start monitoring.

(Kali) Commands: sudo apt update Then sudo apt upgrade -yon the Kali machine, to update the system. Result: All packages are already updated ( All packages are up to date), no changes.

Don't install Wireshark because we don't need it in Cali. Commands: sudo apt install curl -y ,sudo apt install wget -yon Kali, to ensure the availability of analysis and communication tools. Result: The three packages are pre-installed with the latest version (Wireshark 4.6.6-1, curl 8.20.0-5, wget 1.25.0-2).

Commands: sudo apt install dnsutils -y, sudo apt install openssh-client -y, sudo apt install netcat-openbsd -yon Kali, to prepare the DNS scanning and network connection tools (SSH and netcat). Result: All tools are pre-installed and ready to use (bind9-dnsutils, openssh-client 1 : 10.3p1-5, netcat-openbsd 1.238-1).

Commands: sudo wireshark On Ubuntu to run the packet analyzer. Result: The Wireshark welcome screen opened with a list of previous files ( nmap-activity-detection.pcapngone present, and two others missing), and an interface selected ens33for capture.

Commands: curl http://192.168.81.129from Kali, to test access to the web server on Ubuntu. Result: Successful response displaying the default Ubuntu Apache2 page (full HTML), confirming that the service is responding to HTTP requests.

Commands: A for i in {1..10}; do curl http://192.168.81.129; doneKali loop to generate repetitive HTTP requests to the server. Result: 10 consecutive requests successfully initiated, each returning the default Apache page — simulating a repetitive/suspicious connection.

Commands: nslookup bitpluss.comthen nslookup ubunyu.com(domain name identical to ubuntu.com, likely a phishing/typing domain) from Kali. Result: Multi-domain analysis succeeded bitpluss.com, while ubunyu.comNXDOMAIN error analysis failed — documenting an attempt to access a suspicious domain that looked like a legitimate domain (typosquatting).

Commands: ssh Mubarak@192.168.81.129 From Kali to connect to the Ubuntu machine via a user named Mubarak, then execute pwd, ls, and exit. Result: Login successful (a previous connection activity from the same machine 192.168.81.128 according to the log), the user directory was found to contain snaponly a folder, then the session was successfully terminated.

Commands: nc -vz 192.168.81.129 4444 Then, nc -vz 192.168.81.129 9999from Kali, to check two common ports often used in command and control (C2) communications or penetration testing tools (such as Metasploit). Result: Both ports are rejected (Connection refused), meaning they are blocked on the target machine.

Commands: nc -vz 192.168.81.129 21 Then nc -vz 192.168.81.129 23from Kali, to check the FTP and Telnet ports. Result: Both ports are also refused (Connection refused), confirming that these services are not available on the target.

Commands: Live Capture via Wireshark on an interface ens33in Ubuntu. Result: Logging 1372 diverse packets including DNS (including a failed query for ubunyu.comNXDOMAIN in packet 210), NTP, ARP, and ICMPv6 — comprehensive documentation of network traffic during suspicious tests.

Commands: Open a menu Filein Wireshark during live capture in preparation for saving. Result: Save options appear while capturing continues (counter reaches 1374 packets), temporary file named wireshark_ens33Q39MS3.pcapng.

Commands: File > Save AsIn Wireshark, to save the capture with a permanent name. Result: Specifies the path /home/soc-lab/Desktopand filename suspicious-connections-analysis.pcapngin an uncompressed format.

Commands: Open a menu Statistics after saving the file suspicious-connections-analysis.pcapng, hovering the cursor over it Capture File Properties. Result: Prepares to display comprehensive statistical file details.

Commands: Statistics > Capture File Propertieson the saved file. Result: Displaying full file details — 1374 packets, size 345 KB, capture time 00:07:38 , average 3.0 packets/second and 5,218 bits/second — thus documenting the entire suspicious communications analysis session.

Commands: Open a menu Statistics by hovering the cursor over Protocol Hierarchya file in Wireshark suspicious-connections-analysis.pcapng. Result: Prepared to display the protocol hierarchy within the captured file.

Commands: Statistics > Protocol Hierarchy. Result: Detailed distribution of protocols — IPv4 accounts for 95.2% of the packets, TCP accounts for 86.1%, and SSH alone accounts for 68.4% of the packets (940 packets), while HTTP accounts for only 1.7% — a clear indication that most of the traffic is repeated SSH connection attempts.

Commands: Open a menu Statistics by hovering the cursor over it Endpoints. Result: Prepares to display a list of endpoints involved in the network traffic.

Commands: Statistics > Endpoints With the IPv4 tab displayed. Result: Displaying 15 IPv4 endpoints — the most prominent being 192.168.81.1281,151 packets (243 KB) and 192.168.81.1291,269 packets (291 KB), which are the two main parties involved in the suspicious traffic exchange.

Commands: Open a menu Statisticsby hovering the cursor over it Conversations. Result: Prepared to display network conversations between different parties.

Commands: Statistics > Conversations With the IPv4 tab displayed. Result: Displaying 14 conversations — the most prominent being the conversation between [username] 192.168.81.128and 192.168.81.129[username] with a size of 1,113 packets (239 KB) and a high transmission speed (up to 3,722 kbps), which is the dominant conversation that needs deeper examination.

Commands: Applying the display filter tcp in Wireshark. Result: Displaying 1183 packets (86.1%) showing a recurring pattern of HTTP connections (SYN → SYN/ACK → GET → 200 OK → FIN) between ports 33114/58564/58570 and port 80, at a regular recurrence rate of ~46 seconds — behavior resembling an automated (scripted) server scan.

Commands: Apply a filter http to display only HTTP traffic. Result: Displays 24 packets (1.7%) showing recurring GET requests from 192.168.81.128and to 192.168.81.129at regular intervals (~13 seconds), with request details visible in the hexadecimal header, indicating the use of curl's User-Agent.

Commands: Apply a filter tcp.port == 22 to display SSH traffic exclusively. Result: Displaying 973 packets (70.8%) detailing a complete SSH session — from the TCP handshake, SSH-2.0 protocol exchange (OpenSSH 10.3p1 client-side and OpenSSH 10.2p1 Ubuntu server-side), through key exchange, and even the repeated encrypted packets — documenting the unusually large volume of SSH connections.

Commands: Apply a filter dns to display DNS traffic only. Result: Displays 22 packets (1.6%) including successful queries (bitpluss.com, connectivity-check.ubuntu.com, changelogs.ubuntu.com) plus the suspicious failed query ubunyu.comthat returned an NXDOMAIN error in packet 210.

Commands: Apply a filter tcp.flags.reset == 1 to isolate reset packets (RST) indicating rejected connections. Result: Displaying only 6 packets (0.4%), including rejected connections on suspicious ports 4444 and 9999 (commonly used in C2 tools such as Metasploit) as well as 21 (FTP) and 23 (Telnet) — documenting failed scanning attempts on sensitive ports.

Commands: Apply a filter tcp.flags.syn == 1 && tcp.flags.ack == 0 to isolate only SYN packets, to identify all attempts to establish new connections. Result: Displays 20 packets (1.5%) documenting all initial connection attempts across multiple ports (80, 22, 443, 4444, 9999, 21, 23), including a TCP retransmission on port 443—a comprehensive log of all connections initiated by the device 192.168.81.128towards the various targets, summarizing the entire suspicious activity in this exercise.
