SSH Attack Detection

In this task, we will perform SSH attack detection. If you don't have your own laptop, I have set up a virtual one for you. set up your own lab

Type the command `ip a` to find the IP address of the Kali machine.

Type the command `ip a` to find the victim's IP address in Ubuntu.

We ran the command `sudo systemctl status ssh`, and the results show that the service is active and listening for connections on the default port 22.

As a security analyst, your task is to connect to the target machine within the company. Use the following command to establish an SSH connection: `ssh soc-analyst@192.168.150.129`. If prompted for a password, enter the user's password, not the Kali machine's password. There is a more professional method for retrieving files from the victim's machine, which we will cover later.

Use the command `touch passwords.txt` to create a file in which we will write passwords.

Then, use the command `nano passwords.txt` to open the file.

Type these passwords—123456, password, admin, root, qwerty, Password123 Add the correct user password to it, because we need a successful login in the log file. —then press Ctrl+O to save, Enter to confirm, and finally Ctrl+X to exit.

In this step, we used the Hydra tool to execute a brute-force attack using the command `hydra -l soc-analyst -P ssh://192.168.150.129`

sudo scp soc-analyst@192.168.150.129:/var/log/auth.log ~/Desktop

After executing the brute-force attack, we move on to the most critical step: transferring the log file from the victim's machine to analyze it elsewhere. The goal is to preserve the evidence in its original state—this is the step I mentioned to you earlier.

After transferring the `auth.log` file from the victim's machine to the analyst's Kali machine, we use the `cat auth.log` command to view the logs. These logs contain records of both failed and successful login attempts—specifically, the successful login achieved when we executed the brute-force attack using the Hydra tool. We will see that now.

As we can see, there are repeated failed login attempts from IP address 192.168.150.129. The system shows attempts to mitigate the attack by imposing time-based restrictions; however, the attacker ultimately succeeded in guessing the password and gaining access to the system. The system initiated the process, and a work session was opened.

In this step, we will prepare a Python script. This is the fastest and most widely used method, as it greatly facilitates the analysis process compared to manual work. Create a file using the command `touch ssh_attack_detector.py` (you can name it whatever you like), then open the file using the `nano` command.

After opening the file, write this script. then press Ctrl+O to save, Enter to confirm, and finally Ctrl+X to exit.

After running the script, the following results appeared: failed brute-force login attempts and successful logins were detected, and the IP address responsible for both the failed and successful attempts was identified as 192.168.150.129.
