Suspicious IP Detection

You can carry out this task practically in an isolated virtual lab if you do not have one you can set up your own lab using the provided link.

In this task we will analyze system logs to identify a suspicious IP address and then launch an attack against the victim's machine to generate logs.

The first step is to gather some information about the victim before launching the attack We use the `ip a` command to identify the victim's IP address and the results show that the address is 192.168.150.129.

The command `sudo systemctl status ssh` is used to check the status of the SSH service and the results indicate that it is running.

In this step we carry out a manual attack by entering each user's password incorrectly.

ssh admin@192.168.150.129

ssh developer@192.168.150.129

ssh IT-support@192.168.150.129

We will stop here this is all we need to analyze in the log file.

At this stage you are acting as an SOC analyst

sudo grep "Failed password" /var/log/auth.log

This command searches the authentication log file for all failed login attempts.

The results show failed login attempts using the non-existent username "admin" as well as failed login attempts via the users "developer" and "IT-support"

sudo grep "Failed password" /var/log/auth.log | grep -oE "from [0-9.]+" | sort | uniq -c

It is used to count the number of failed login attempts per IP address.

As we can see, there are 9 failed attempts from IP 192.168.150.128.

sudo grep "Failed password" /var/log/auth.log | grep -oE "for [a-zA-Z0-9-]+" | sort | uniq -c

The purpose of this command is to count the number of failed login attempts for each username.

As we can see the results show three failed attempts using the 'developer' user three failed attempts using the 'IT-support' user and three failed attempts using a non existent user (admin).

'sudo grep "Failed password for root" /var/log/auth.log'

Its purpose is to look for any failed login attempts to the root account via SSH.

The results also show that there are no failed or successful login attempts via root.

sudo grep "Invalid user" /var/log/auth.log

Its function is to search the authentication log '/var/log/auth.log' for all attempts targeting users that do not exist on the system.

This type of result indicates a reconnaissance process or the beginning of a username and password guessing attack.

sudo iptables -A INPUT -s 192.168.150.128 -j DROP

After identifying the IP address responsible for the failed login attempts we are applying a ban to that IP (192.168.150.128) However there is an error regarding the IP we blocked when applying the ban you should block the attacker's machine IP.

This adds a rule to the iptables firewall to block all inbound packets from a specific IP address.

This is an optional step if you want to lift the IP ban as you will need to run tests between the two devices later on.
