Brute Force Detection

In this mission, we will perform a brute-force attack to obtain failed login attempts. If you don't have your own laptop, I have set up a virtual one for you. set up your own lab

To find the victim's IP address, type the command ip a

we used The command ping 192.168.150.129 to check if the victim's device is connected or not.

To check if the SSH service is working, use the command `sudo systemctl status ssh`. As shown in the image, it appears active.

The command `sudo apt update` is used to update the operating system's package list.

we used The command `sudo apt install openssh-server y` to install the OpenSSH Server package on the system, with the `y` option automatically approving any installation-related prompts.

`sudo systemctl enable ssh`. This command configures the SSH service to run automatically when the system boots up.

The command `sudo systemctl start ssh` aims to immediately start the SSH service in the current system session.

In this step, we create a user account to test failed login attempts later. Create a simple password so you don't forget the following steps: just press Enter and finally, "y" which means "yes".

We use the `sudo ufw status` command to check the firewall status.

The command `sudo ufw allow ssh` is used to add a rule in the firewall that allows server traffic to pass through the SSH service.

We use the command `sudo ufw disable` to completely disable the firewall on the system, which is what we need.

`ssh barak@192.168.150.129` This command connects to a user named Barak. Here, we connect to the user's machine as an analyst working for the same company and with access privileges, because we will later need to access some files on the user's or victim's machine. Enter the password we previously created for this user.

The user's device was connected so that you, as a security analyst in the company, could access any file you wanted, but there is a better method that we will learn about later in this task.

Press exit to exit and return to Kali.

`sudo apt` to update the system package list

'sudo apt install hydra -y' In this step, we install the Hydra tool, which we will use to perform a brute-force attack.

'hydra -h' to find out information about the tool and the protocols that can be targeted, such as SSH, FTP, HTTP, etc.

'nano passwords.txt' After downloading Hydra, the next step is to create a file and write down the passwords that Hydra will use later. Name the file passwords.txt or whatever you want. Then press Enter

We used the nano passwords.txt command to open the file and write the passwords. You can write these passwords 123456 , password , admain, qwerty , welcome , root , toor , abc123, but make sure you don't enter the correct user password because that will successfully log you in, and that's not what we want.

Now we perform a brute-force attack using the command 'hydra -l barak -P passwords.txt ssh://192.168.150.129'

'-l barak' Specify the target username as barak

'-P passwords.txt' Use an external file containing passwords

'ssh://192.168.150.129' Specify the protocol and IP address of the target device

We used the command `sudo scp barak@192.168.150.129:/var/log/auth.log ~/Desktop` to copy the authentication log files from the user's device, but we received a rejection. The reason is that the authentication log file is very sensitive and its permissions are usually limited to root. However, we will address this issue in a few simple steps. If you recall, in one of the steps, we connected to the user's device as an analyst with privileges, and we agreed that we would find another way to do so. This is the second method to obtain files from the victim's device and analyze them remotely, preserving the victim's device details without any changes that could affect the results.

We used the command `ls -l /var/log/auth.log` to locate this file and also to determine its permissions.

We use the command `sudo cp /var/log/auth.log ~/auth_copy.log` to create a copy of the log file because we will be transferring a copy of the log file to an external machine for analysis.

'sudo' Run the command with root privileges

'cp' is the copy command in Linux

'/var/log/auth.log' The source file to be copied is the log file.

The `~/auth_copy.log` path and new file name are used to create a copy of the authentication log file within the user's home directory. We will now retrieve the file from our external device, having established that a copy of the log file exists in the home directory.

'~' home directory.

'ls -l' To view the file and see its permissions

`sudo chmod 644 auth_copy.log` changes file permissions.

6 (File Owner): Read and write privileges.

4 (Group): Read-only privileges.

4 (Others): Read-only privileges.

'cp soc-analyst@192.168.150.129:~/auth_copy.log ~/Desktop/' The file was transferred successfully

'scp' is a tool used for transferring data between two hosts via the SSH protocol and ensures data encryption during transmission.

'soc-analyst' The username on the victim's device where the file is stored file copy

'192.168.150.129' Victim's device IP address

'~/auth_copt.log' The path where the file is located on the victim's device

'~/Desktop' This is the path or destination where the file will be stored on the Kali device.

The command `cd Desktop` moves to the folder, then the command `ls -l` displays the contents within the Desktop. As you can see, the file was successfully installed.

Then we executed the command 'grep "Failed password" auth_copy.log' This command will display all the lines containing "failed password" As we can see, we were able to successfully obtain the failed login attempts.

In this step, we will create a Python script, which greatly assists in the analysis. Sometimes we may have a lot to analyze, and it may be difficult for us to do so manually.

'touch analyzzer.py' Create a file named analyzer.py

'nano analyzer.py' to open the file and write the Python script

You can get the script via GitHub link. You can also write your own script if you want.

After writing the script, press Ctrl+O to save, then Enter, and finally Ctrl+X to exit.

Run the script now using the command 'python3 analyzer.py' This script will save you a lot of time and effort.

The results show that IP address 192.168.150.130 caused 11 failed login attempts, which is not the behavior of a normal user, confirming that this was a brute-force attack. That's the end of this task. Don't forget to support me so we can continue learning. Thank you, friends.
