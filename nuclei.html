Introduction — What is Nuclei?

Nuclei is a fast, template-based vulnerability scanner developed by ProjectDiscovery. It sends targeted requests to targets based on YAML templates — each template checks for a specific vulnerability, misconfiguration, or exposed asset. With thousands of community templates covering CVEs, misconfigurations, exposed panels, and more, Nuclei is one of the most powerful tools in modern security testing.

What Makes Nuclei Different?

Unlike traditional scanners that use fixed signatures, Nuclei uses community-driven YAML templates — anyone can write, share, and use them. This means new vulnerabilities get templates within hours of disclosure.

What Can Nuclei Do?

Detect CVEs and known vulnerabilities — Find exposed admin panels — Discover misconfigurations — Identify default credentials — Detect exposed files and secrets — Perform network protocol scanning — DNS enumeration — SSL/TLS checks — Custom template-based checks.

Nuclei vs Other Scanners

Nuclei       — Template-based, fast, community-driven
               Best for: CVE scanning, bulk targets, custom checks

Nessus       — Commercial, comprehensive, GUI
               Best for: Enterprise compliance scanning

OpenVAS      — Open-source Nessus alternative
               Best for: Network vulnerability assessment

Nikto        — Web-focused, older, noisy
               Best for: Quick web server checks

Burp Scanner — Deep web app testing, proxy-based
               Best for: Manual + automated web app testing

Legal Warning

Nuclei sends real HTTP requests and exploit attempts. Only scan targets you own or have explicit written permission to test. Unauthorized scanning is illegal and can cause unintended damage to production systems.

Templates — The Core of Nuclei

What is a Template?

A Nuclei template is a YAML file that defines exactly what request to send, what to look for in the response, and how to classify the finding. Templates are the heart of Nuclei — every scan you run is powered by them.

Severity Levels

critical   — Remote code execution, authentication bypass,
             full system compromise
high       — SQL injection, stored XSS, SSRF, significant data exposure
medium     — Reflected XSS, CSRF, open redirect, info disclosure
low        — Missing headers, verbose errors, minor misconfigs
info       — Technology detection, version disclosure, interesting findings
unknown    — Severity not yet determined

Rate Limiting, Performance, and Stealth

Controlling Request Rate

# Limit requests per second (default: 150)
nuclei -u https://target.com -rate-limit 50

# Very slow — stealthy scan
nuclei -u https://target.com -rate-limit 5

# Very fast — internal lab
nuclei -u https://target.com -rate-limit 500

# Set maximum bulk size (requests per host, default: 25)
nuclei -u https://target.com -bulk-size 10

# Set concurrency (parallel template executions, default: 25)
nuclei -u https://target.com -c 10

Timeout and Retry Settings

# Set request timeout in seconds (default: 10)
nuclei -u https://target.com -timeout 5

# Set number of retries (default: 1)
nuclei -u https://target.com -retries 3

# Set max host errors before skipping (default: 30)
nuclei -u https://target.com -max-host-error 5

Proxy Support

# Route through a proxy (Burp Suite)
nuclei -u https://target.com \
       -proxy http://127.0.0.1:8080

# Route through SOCKS5 (Tor)
nuclei -u https://target.com \
       -proxy socks5://127.0.0.1:9050

# Use a list of proxies (rotates automatically)
nuclei -u https://target.com \
       -proxy-list proxies.txt

Writing Custom Templates

Template Skeleton

id: my-custom-check

info:
  name: My Custom Vulnerability Check
  author: yourname
  severity: medium
  description: |
    Checks for a custom vulnerability condition.
  tags: custom,exposure

requests:
  - method: GET
    path:
      - "{{BaseURL}}/target/path"

    matchers-condition: and
    matchers:
      - type: word
        words:
          - "vulnerable_string"
        part: body

      - type: status
        status:
          - 200

Template Variables

{{BaseURL}}      — Full base URL (https://target.com)
{{RootURL}}      — Root URL without path
{{Hostname}}     — Hostname only (target.com)
{{Host}}         — Host with port if non-standard
{{Port}}         — Port number
{{Path}}         — URL path
{{Scheme}}       — http or https
{{Username}}     — Username (from -var)
{{Password}}     — Password (from -var)

Matcher Types

# Word matcher — check for strings
matchers:
  - type: word
    words:
      - "root:x:0:0"
      - "daemon:"
    condition: or      — any word matches (default)
    # condition: and   — all words must match
    part: body         — where to match: body/header/all/response

# Regex matcher
matchers:
  - type: regex
    regex:
      - "([a-zA-Z0-9]{32})"          — 32-char hash
      - "password\\s*=\\s*['\"][^'\"]+['\"]"  — password in config

# Status code matcher
matchers:
  - type: status
    status:
      - 200
      - 301

# Size matcher
matchers:
  - type: size
    size:
      - 1234          — Exact size match

# Binary matcher
matchers:
  - type: binary
    binary:
      - "504B0304"    — ZIP file magic bytes (hex)

# DSL matcher — complex logic expressions
matchers:
  - type: dsl
    dsl:
      - "status_code == 200 && len(body) > 100"
      - "contains(header, 'X-Powered-By')"

Extractor Types

# Extract data from responses
extractors:
  - type: regex
    name: version
    regex:
      - "Apache/([0-9.]+)"
    group: 1           — capture group number

  - type: kval
    kval:
      - server         — extract Server header value

  - type: xpath
    xpath:
      - "//title"      — extract page title

  - type: json
    json:
      - ".version"     — extract JSON field

  - type: dsl
    dsl:
      - "header"       — extract entire header

POST Request Template

id: login-default-credentials

info:
  name: Default Login — admin/admin
  author: yourname
  severity: high
  tags: default-login,panel

requests:
  - method: POST
    path:
      - "{{BaseURL}}/admin/login"
      - "{{BaseURL}}/login"

    headers:
      Content-Type: application/x-www-form-urlencoded

    body: "username=admin&password=admin"

    matchers-condition: and
    matchers:
      - type: word
        words:
          - "dashboard"
          - "logout"
          - "welcome"
        condition: or
        part: body

      - type: status
        status:
          - 200
          - 302

Multi-Request Template

id: multi-step-check

info:
  name: Multi-Step Vulnerability Check
  author: yourname
  severity: high

requests:
  # Request 1 — Get CSRF token
  - method: GET
    path:
      - "{{BaseURL}}/login"

    extractors:
      - type: regex
        name: csrf_token
        regex:
          - 'name="csrf" value="([a-f0-9]+)"'
        group: 1
        internal: true   — store for use in next request

  # Request 2 — Submit with extracted token
  - method: POST
    path:
      - "{{BaseURL}}/login"

    body: "username=admin&password=admin&csrf={{csrf_token}}"

    matchers:
      - type: word
        words:
          - "welcome admin"
        part: body

Network Template (Non-HTTP)

id: redis-unauth

info:
  name: Redis Unauthenticated Access
  author: yourname
  severity: critical
  tags: redis,network,unauth

network:
  - inputs:
      - data: "PING\r\n"

    host:
      - "{{Hostname}}:6379"

    read-size: 2048

    matchers:
      - type: word
        words:
          - "+PONG"

Nuclei Cheat Sheet

Core Options

-u URL          — Single target URL
-l file         — Targets from file
-t path         — Template or directory
-id template-id — Run specific template by ID
-w workflow     — Run workflow template
-update         — Update Nuclei binary
-update-templates — Update template library
-tl             — List all templates
-version        — Show version

Filtering Options

-tags tags      — Filter by tags (cve,rce,xss...)
-etags tags     — Exclude tags
-severity lvl   — Filter by severity (critical,high,medium,low,info)
-exclude-severity — Exclude severity levels
-author name    — Filter by template author
-id ID          — Filter by template ID
-exclude-id ID  — Exclude template ID

Performance Options

-c N            — Concurrency (default: 25)
-rate-limit N   — Requests per second (default: 150)
-bulk-size N    — Requests per host (default: 25)
-timeout N      — Request timeout in seconds (default: 10)
-retries N      — Retry failed requests (default: 1)
-max-host-error N — Skip host after N errors (default: 30)
-p N            — Delay between requests

Request Options

-H "Header"     — Custom HTTP header
-proxy URL      — HTTP/SOCKS5 proxy
-proxy-list     — Proxy list file
-var key=val    — Template variable
-header-file    — Headers from YAML file

Output Options

-o file         — Output to file
-json           — JSON output format
-jsonl          — JSON lines format
-markdown-export — Markdown report folder
-sarif-export   — SARIF output file
-v              — Verbose
-vv             — Very verbose
-silent         — Results only
-stats          — Show statistics
-nc             — No color

Most Used Commands

# Quick CVE scan
nuclei -u https://target.com -t cves/ -severity critical,high -c 20

# Full scan
nuclei -u https://target.com -t cves/ -t vulnerabilities/ \
       -t exposures/ -t misconfigurations/ -c 30 -o results.txt

# Bulk scan from file
nuclei -l targets.txt -t cves/ -json -o results.jsonl -stats

# Technology detection
nuclei -u https://target.com -t technologies/ -severity info

# Default credential scan
nuclei -u https://target.com -t default-logins/

# Stealth scan
nuclei -u https://target.com -rate-limit 10 -t 5 -c 5

# Bug bounty pipeline
subfinder -d target.com -silent | httpx -silent | \
nuclei -t cves/ -t exposures/ -severity critical,high \
       -json -o bb_results.jsonl

# Validate custom template
nuclei -validate -t my-template.yaml

# Debug custom template
nuclei -u https://target.com -t my-template.yaml -debug
