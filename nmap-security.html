Introduction — What is Nmap?

Nmap (Network Mapper) is the most widely used network scanning tool in cybersecurity. It was created by Gordon Lyon in 1997 and is now a standard tool for penetration testers, system administrators, and security researchers worldwide.

What Can Nmap Do?

Discover live hosts on a network — Find open ports and services — Detect operating systems — Identify software versions — Run security scripts — Map entire networks in minutes.

Who Uses Nmap?

Penetration testers — Network administrators — Security auditors — CTF players — Anyone who needs to understand what is running on a network.

Installation

# Linux (Debian/Ubuntu)
sudo apt install nmap

# Linux (Red Hat/Fedora)
sudo dnf install nmap

# macOS
brew install nmap

# Windows
# Download installer from https://nmap.org/download.html

Requirements

Basic understanding of networking (IP addresses, ports, protocols). Always scan only networks you own or have written permission to test — unauthorized scanning is illegal.

Nmap Basics — Your First Scan

Basic Syntax

nmap [options] [target]

The target can be a single IP, a hostname, a range, or a subnet.

Target Specification

nmap 192.168.1.1              — Single IP
nmap 192.168.1.1-50           — IP range
nmap 192.168.1.0/24           — Entire subnet (256 hosts)
nmap 10.0.0.0/8               — Large network
nmap scanme.nmap.org          — Hostname
nmap 192.168.1.1 192.168.1.5  — Multiple targets
nmap -iL targets.txt          — Read targets from a file
nmap --exclude 192.168.1.5    — Exclude a specific host

Your First Scan

nmap 192.168.1.1

This runs a default scan — sends SYN packets to the 1000 most common ports and reports which are open, closed, or filtered.

Understanding the Output

PORT     STATE    SERVICE
22/tcp   open     ssh
80/tcp   open     http
443/tcp  open     https
8080/tcp filtered http-proxy
3306/tcp closed   mysql

STATE meanings:
open     — A service is listening on this port
closed   — Port is reachable but no service listening
filtered — Firewall is blocking the probe — state unknown
Host Discovery

What is Host Discovery?

Before scanning ports, Nmap checks which hosts are alive on the network. By default it sends ICMP echo requests (ping) and TCP probes. Understanding how to control this is key for stealthy or thorough scanning.

Common Host Discovery Options

nmap -sn 192.168.1.0/24       — Ping scan only — no port scan
                                 (discover live hosts fast)

nmap -Pn 192.168.1.1          — Skip host discovery — treat all
                                 hosts as alive (useful when ICMP
                                 is blocked by firewall)

nmap -PS 192.168.1.0/24       — TCP SYN ping (port 80 by default)
nmap -PS22,80,443             — TCP SYN ping on specific ports

nmap -PA 192.168.1.0/24       — TCP ACK ping
nmap -PU 192.168.1.0/24       — UDP ping

nmap -PE 192.168.1.0/24       — ICMP echo ping (standard ping)
nmap -PP 192.168.1.0/24       — ICMP timestamp ping
nmap -PM 192.168.1.0/24       — ICMP netmask ping

nmap -PR 192.168.1.0/24       — ARP ping — fastest on local network

Practical Examples

# Quickly find all live hosts on your local network
nmap -sn 192.168.1.0/24

# Scan even if hosts don't respond to ping
nmap -Pn 10.0.0.1-100

# Discover hosts using ARP (most reliable on LAN)
sudo nmap -PR -sn 192.168.1.0/24

DNS Resolution

nmap -n 192.168.1.0/24        — Never do DNS resolution (faster)
nmap -R 192.168.1.0/24        — Always resolve DNS
nmap --dns-servers 8.8.8.8    — Use a specific DNS server
Port Scanning Techniques

Why Different Scan Types?

Different scan techniques produce different network traffic. Some are faster, some are stealthier, and some work better against certain firewall configurations. Choosing the right scan type matters in real engagements.

TCP SYN Scan — -sS (Default and Most Common)

sudo nmap -sS 192.168.1.1

Sends a SYN packet — if the port responds with SYN/ACK it is open — Nmap sends RST without completing the handshake. Called "half-open" scan. Fast, stealthy, and requires root. This is the default when running as root.

TCP Connect Scan — -sT

nmap -sT 192.168.1.1

Completes the full TCP three-way handshake. Does not require root. Slower and more detectable — logged by the target. Default when not running as root.

UDP Scan — -sU

sudo nmap -sU 192.168.1.1

Scans UDP ports. Much slower than TCP. Important — many critical services use UDP: DNS (53), DHCP (67/68), SNMP (161), NTP (123).

# Combine TCP and UDP scan
sudo nmap -sS -sU 192.168.1.1

Stealth / Evasion Scans

nmap -sN 192.168.1.1   — NULL scan — no flags set
nmap -sF 192.168.1.1   — FIN scan — only FIN flag
nmap -sX 192.168.1.1   — Xmas scan — FIN, PSH, URG flags set

These scans can bypass some stateless firewalls and packet filters. Closed ports reply with RST — open ports do not respond. Do not work reliably against Windows systems.

ACK Scan — -sA

sudo nmap -sA 192.168.1.1

Does not determine open/closed — used to map firewall rules and determine if ports are filtered or unfiltered.

Port Specification

nmap -p 80 192.168.1.1          — Scan port 80 only
nmap -p 80,443,22               — Scan specific ports
nmap -p 1-1000                  — Scan port range
nmap -p-                        — Scan all 65535 ports
nmap --top-ports 100            — Scan top 100 most common ports
nmap -p U:53,T:80               — UDP port 53 and TCP port 80
Service and Version Detection

Why Detect Versions?

Knowing that port 80 is open is useful — knowing it runs Apache 2.4.49 with a known RCE vulnerability is critical. Version detection transforms a list of open ports into actionable intelligence.

Version Detection — -sV

nmap -sV 192.168.1.1

Probes open ports and tries to determine the service name and exact version number.

PORT    STATE SERVICE VERSION
22/tcp  open  ssh     OpenSSH 8.2p1 Ubuntu 4ubuntu0.5
80/tcp  open  http    Apache httpd 2.4.41 ((Ubuntu))
3306/tcp open mysql   MySQL 8.0.28

Intensity Levels

nmap -sV --version-intensity 0   — Lightest — fastest — less accurate
nmap -sV --version-intensity 5   — Default
nmap -sV --version-intensity 9   — Most aggressive — most accurate
nmap -sV --version-all           — Try every probe (same as intensity 9)
nmap -sV --version-light         — Fastest (same as intensity 2)

OS Detection — -O

sudo nmap -O 192.168.1.1

Analyzes TCP/IP stack behavior to guess the operating system and version.

OS details: Linux 4.15 - 5.6
OS details: Windows 10 1903 - 21H2
OS details: Cisco IOS 15.2
  
sudo nmap -O --osscan-guess 192.168.1.1   — Guess even with low confidence

Aggressive Scan — -A

sudo nmap -A 192.168.1.1

Enables: OS detection (-O) + Version detection (-sV) + Script scanning (-sC) + Traceroute (--traceroute). The most thorough single-flag option — but loud and detectable.

Nmap Scripting Engine (NSE)

What is NSE?

The Nmap Scripting Engine allows Nmap to run Lua scripts against targets — automating tasks like vulnerability detection, brute forcing, service enumeration, and more. Over 600 scripts are included with Nmap.

Script Categories

auth        — Authentication and credential testing
brute       — Brute force attacks against services
default     — Safe scripts run with -sC
discovery   — Enumerate information about services
dos         — Denial of service tests (use carefully)
exploit     — Actual exploitation scripts
external    — Scripts that contact external resources
fuzzer      — Send unexpected data to find bugs
intrusive   — May crash or disrupt services
malware     — Detect malware or backdoors
safe        — Unlikely to cause harm
version     — Extends version detection
vuln        — Check for known vulnerabilities

Running Scripts

nmap -sC 192.168.1.1                   — Run default scripts
nmap --script=http-title 192.168.1.1   — Run a specific script
nmap --script=vuln 192.168.1.1         — Run all vuln scripts
nmap --script=http-* 192.168.1.1       — Run all http scripts
nmap --script=safe 192.168.1.1         — Run all safe scripts
nmap --script=brute 192.168.1.1        — Run all brute scripts

Useful Scripts by Category

# HTTP enumeration
nmap --script=http-title,http-headers,http-methods -p 80,443 192.168.1.1
nmap --script=http-robots.txt -p 80 192.168.1.1
nmap --script=http-shellshock -p 80 192.168.1.1

# SMB enumeration
nmap --script=smb-enum-shares,smb-enum-users -p 445 192.168.1.1
nmap --script=smb-vuln-ms17-010 -p 445 192.168.1.1   — EternalBlue check

# FTP
nmap --script=ftp-anon,ftp-bounce -p 21 192.168.1.1   — Anonymous login

# SSH
nmap --script=ssh-auth-methods -p 22 192.168.1.1
nmap --script=ssh-brute -p 22 192.168.1.1

# MySQL
nmap --script=mysql-info,mysql-databases -p 3306 192.168.1.1

# Vulnerability scan
nmap --script=vuln 192.168.1.1

Passing Script Arguments

nmap --script=http-brute --script-args userdb=users.txt,passdb=pass.txt -p 80 192.168.1.1
nmap --script=smb-brute --script-args smbuser=admin -p 445 192.168.1.1

Finding Scripts

# List all scripts
ls /usr/share/nmap/scripts/

# Search for scripts by keyword
nmap --script-help "*smb*"
locate *.nse | grep ssh
Timing and Performance

Timing Templates — -T

Nmap has six timing templates that control scan speed — from paranoid (slowest, stealthiest) to insane (fastest, loudest).

-T0  Paranoid    — 5 minute delay between probes — IDS evasion
-T1  Sneaky      — 15 second delay — slow IDS evasion
-T2  Polite      — 0.4 second delay — less bandwidth
-T3  Normal      — Default — balanced speed and accuracy
-T4  Aggressive  — Faster — assumes reliable network
-T5  Insane      — Maximum speed — may miss results
  
# Fast internal network scan
nmap -T4 192.168.1.0/24

# Slow stealthy external scan
nmap -T1 10.10.10.5

# CTF / lab environment
nmap -T5 10.10.10.0/24

Fine-Tuning Performance

nmap --min-rate 1000 192.168.1.1    — Send at least 1000 packets/sec
nmap --max-rate 500 192.168.1.1     — Limit to 500 packets/sec
nmap --min-parallelism 10           — At least 10 probes in parallel
nmap --max-parallelism 1            — One probe at a time (slow)
nmap --host-timeout 30s             — Give up on a host after 30 seconds
nmap --max-retries 1                — Only retry once per port

Recommended Combinations

# Fast full scan for CTF / internal lab
sudo nmap -sS -sV -O -T4 --min-rate 5000 -p- 10.10.10.5

# Stealthy scan for real engagement
sudo nmap -sS -T2 --max-rate 100 -p 1-10000 10.10.10.5

# Quick host discovery on large network
nmap -sn -T4 --min-rate 1000 192.168.0.0/16
Firewall and IDS Evasion

Why Evasion Matters

In real penetration tests, firewalls and Intrusion Detection Systems (IDS) may block or alert on your scans. Nmap has built-in techniques to make scans harder to detect or block.

Fragmentation

sudo nmap -f 192.168.1.1         — Fragment packets into 8-byte chunks
sudo nmap -ff 192.168.1.1        — 16-byte fragments
sudo nmap --mtu 24 192.168.1.1   — Custom MTU (must be multiple of 8)

Splits packets into tiny fragments — some older firewalls and IDS cannot reassemble and inspect them.

Decoys

sudo nmap -D 10.0.0.1,10.0.0.2,ME 192.168.1.1

Makes the scan appear to come from multiple IP addresses. ME represents your real IP. The target sees traffic from all decoy IPs — harder to identify the real scanner.

# Use random decoys
sudo nmap -D RND:10 192.168.1.1   — 10 random decoy IPs

Source Port Manipulation

sudo nmap --source-port 53 192.168.1.1
sudo nmap -g 80 192.168.1.1

Some firewalls allow traffic from trusted ports like DNS (53) or HTTP (80). Setting the source port to these values may bypass naive firewall rules.

Spoofing and Proxies

sudo nmap -S 10.0.0.5 192.168.1.1      — Spoof source IP (results go to spoofed IP)
nmap --proxies socks4://127.0.0.1:9050  — Route through proxy (Tor)

Randomize Hosts

nmap --randomize-hosts 192.168.1.0/24   — Scan hosts in random order
nmap --data-length 25 192.168.1.1       — Append random data to packets

Slow Down to Avoid Detection

nmap -T0 --max-retries 1 192.168.1.1   — Paranoid timing — very slow
Output Formats

Why Save Output?

Always save your Nmap results — you will want to reference them later, share with clients, or import into other tools. Nmap supports multiple output formats.

Output Options

nmap -oN output.txt  192.168.1.1   — Normal — human-readable text
nmap -oX output.xml  192.168.1.1   — XML — for tools like Metasploit
nmap -oG output.gnmap 192.168.1.1  — Grepable — easy for grep/awk
nmap -oA output      192.168.1.1   — All three formats at once
nmap -oS output.txt  192.168.1.1   — Script kiddie format (novelty)

Recommended Workflow

# Always save in all formats — costs nothing
sudo nmap -sS -sV -sC -O -p- -T4 -oA full_scan 192.168.1.1

Verbosity and Debugging

nmap -v   192.168.1.1   — Verbose — show results as they come in
nmap -vv  192.168.1.1   — More verbose
nmap -d   192.168.1.1   — Debug mode
nmap -dd  192.168.1.1   — More debug output
nmap --reason 192.168.1.1  — Show why a port is in a given state
nmap --open 192.168.1.1    — Show only open ports

Parsing Grepable Output

# Extract all open ports from grepable output
grep "open" output.gnmap | awk '{print $2, $5}'

# Find all hosts with port 445 open
grep "445/open" output.gnmap | awk '{print $2}'

# Quick port list for another tool
grep "Ports:" output.gnmap | grep -oP '\d+/open' | cut -d/ -f1 | tr '\n' ','
Practical Scanning Workflows

Methodology — Scan in Stages

Professional penetration testers follow a structured scanning workflow — start fast and broad, then go deep on specific targets.

Stage 1 — Host Discovery

# Find all live hosts fast
sudo nmap -sn -T4 --min-rate 1000 192.168.1.0/24 -oG hosts.gnmap

# Extract live IPs
grep "Up" hosts.gnmap | awk '{print $2}' > live_hosts.txt

Stage 2 — Fast Port Scan

# Scan all 65535 ports quickly
sudo nmap -sS -T4 --min-rate 5000 -p- -iL live_hosts.txt -oA fast_scan

Stage 3 — Deep Scan on Open Ports

# Run version detection and scripts on discovered open ports only
sudo nmap -sV -sC -O -p 22,80,443,445 192.168.1.5 -oA deep_scan

Stage 4 — Vulnerability Scan

sudo nmap --script=vuln -p 22,80,443,445 192.168.1.5 -oA vuln_scan

CTF / Lab One-Liner

sudo nmap -sS -sV -sC -O -T4 --min-rate 5000 -p- --open -oA nmap_full 10.10.10.5

Web Application Recon

sudo nmap -sV -p 80,443,8080,8443 \
  --script=http-title,http-headers,http-methods,http-robots.txt \
  192.168.1.1 -oN web_scan.txt

SMB Enumeration

sudo nmap -p 445 --script=smb-enum-shares,smb-enum-users,smb-os-discovery,\
smb-security-mode,smb-vuln-ms17-010 192.168.1.0/24

Quick UDP Top Ports

sudo nmap -sU --top-ports 20 -T4 192.168.1.1

Nmap Cheat Sheet

Scan Types

-sS   TCP SYN scan (default, requires root)
-sT   TCP Connect scan (no root needed)
-sU   UDP scan
-sN   TCP NULL scan
-sF   TCP FIN scan
-sX   TCP Xmas scan
-sA   TCP ACK scan (firewall mapping)
-sn   Ping scan — no port scan

Host Discovery

-Pn   Skip ping — treat all as alive
-PE   ICMP echo ping
-PS   TCP SYN ping
-PA   TCP ACK ping
-PU   UDP ping
-PR   ARP ping (LAN only)
-n    No DNS resolution

Port Options

-p 80          Specific port
-p 1-1000      Port range
-p-            All 65535 ports
--top-ports 100  Top 100 common ports
--open         Show open ports only

Detection

-sV            Version detection
-O             OS detection
-A             Aggressive (OS+Version+Scripts+Traceroute)
-sC            Default scripts
--script=name  Specific script

Timing

-T0 to -T5     Timing template (0=slowest, 5=fastest)
--min-rate N   Minimum packets per second
--max-rate N   Maximum packets per second

Output

-oN file   Normal text
-oX file   XML
-oG file   Grepable
-oA file   All formats
-v         Verbose
--open     Open ports only
--reason   Show port state reason

Evasion

-f              Fragment packets
-D decoy1,ME   Use decoys
-S IP          Spoof source IP
-g port        Set source port
--randomize-hosts  Random scan order
