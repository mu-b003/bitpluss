HTTP (HyperText Transfer Protocol)

HTTP is the protocol responsible for transferring data between a web browser (Client) and a web server (Server).

When you enter a website URL such as:

https://example.com

the browser sends an HTTP Request to the server, and the server responds with an HTTP Response.

How Does HTTP Work?

1- The user requests a web page.

2- The browser sends an HTTP Request.

3- The server processes the request.

4- The server sends an HTTP Response.

5- The browser displays the result.

Example

        Client ------ Request ------> Server
        Client <----- Response ------ Server

Components of an HTTP Request

Every HTTP request consists of several parts.

1. Request Line

The Request Line contains:

METHOD PATH VERSION

Example:

GET /profile HTTP/1.1

Meaning:

GET = Request method

/profile = Requested resource

HTTP/1.1 = HTTP version

2. Headers

Headers contain additional information about the request.

Host: example.com
User-Agent: Chrome
Cookie: session=abc123

3. Body

The Body contains data sent to the server.

{
  "username": "admin",
  "password": "123456"
}

Components of an HTTP Response

Status Line

Example:

HTTP/1.1 200 OK

Headers

Example:

Content-Type: text/html
Content-Length: 1024

Body

Contains the page content or returned data.

<h1>Welcome</h1>

Common HTTP Methods

GET

Used to retrieve data.

GET /products

A GET request should not modify data on the server.

POST

Used to create new data.

POST /register

Practical example:

{
  "username": "mubarak",
  "password": "123456"
}

PUT

Used to update an entire resource.

PUT /users/5

PATCH

Used to update part of a resource.

PATCH /users/5

Example payload:

{
  "email": "new@email.com"
}

DELETE

Used to remove data.

DELETE /users/5

HEAD

Similar to GET but returns no response body.

Commonly used to determine:

• File size

• File type

• Whether a resource exists

OPTIONS

Returns the methods allowed on a resource.

OPTIONS /api/users

Response:

Allow: GET, POST, PUT

TRACE

Returns the request exactly as received by the server.

Often disabled for security reasons.

CONNECT

Used to establish a tunnel, commonly for HTTPS connections.

HTTP Status Codes

HTTP status codes are divided into five categories.

1xx Informational

100 Continue — Continue sending the request.

2xx Success

200 OK — The request was successful.

201 Created — A new resource was created successfully.

204 No Content — The request succeeded but no data is returned.

3xx Redirection

301 Moved Permanently — Permanent redirection.

302 Found — Temporary redirection.

304 Not Modified — The content has not changed since the last request.

4xx Client Errors

400 Bad Request — Invalid request.

401 Unauthorized — Authentication required.

403 Forbidden — Access denied.

404 Not Found — Resource not found.

405 Method Not Allowed — Method not allowed.

408 Request Timeout — Request timed out.

429 Too Many Requests — Rate limit exceeded.

5xx Server Errors

500 Internal Server Error — Generic server error.

502 Bad Gateway — Invalid gateway response.

503 Service Unavailable — Service unavailable.

504 Gateway Timeout — Gateway timeout.
