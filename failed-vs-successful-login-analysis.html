Failed vs Successful Login Analysis

This is a task you can perform practically in a virtual lab in this task we execute an attack to generate logs If you do not have a virtual lab you can set one up by visiting the link.

We use the `ip a` command to find the victim's device ip address which we will need later when executing the attack. and the ip is 192.168.150.129

The command `sudo systemctl status ssh` is used to check the status of the SSH service and the results indicate that it is running.

We now have what we need the victim's IP address and have confirmed that the SSH service is running.

From here we will begin preparing an attack aimed at generating records.

'ssh IT-support@192.168.150.129'

Try logging in manually enter an incorrect password twice then enter the correct password on the third attempt. After successfully logging in wait a moment then log out.

We previously carried out a manual attack two attempts failed and one succeeded This time we want to generate logs within the authentication files so we will prepare a password list to execute a brute force attack.

Open the file by typing the command `nano passwords.txt`.

Enter incorrect passwords and finally enter the correct user password.

passwords.txt, mustang4evr, mustang4carm141, mustang4989, mustang49, mustang47, mustang4445, mustang438, mustang43, mustang429, mustang4215, mustang4111, mustang4077, mustang40!, mustang3998, mustang3876, mustang37890, mustang377, mustang374, mustang36, mustang351, mustang350, mustang35., mustang3428, mustang342, mustang338, mustang326,

'hydra -l IT-support -P passwords.txt ssh://192.168.150.129'

We used Hydra to execute a brute-force attack using the 'IT-support' user account; the results show that Hydra successfully logged in.

We have generated a sufficient number of records that we will need later.

Here we begin the analysis Think like an SOS analyst.

sudo grep -E "Failed password|Accepted password" /var/log/auth.log

We used the command to extract failed and successful login attempts and it revealed a successful login by the user "IT-support".

The results also show two failed attempts and one successful one this is considered a normal scenario for the first part.

sudo grep -a "Failed password" /var/log/auth.log | awk '{for(i=1;i<=NF;i++) if($i=="from") print $(i+1)}' | sort | uniq -c | sort -nr

This command is used to extract the number of failed login attempts per IP address from the authentication log.

grep -a "Failed password" /var/log/auth.log

Search for failed login attempts

awk '{for(i=1;i<=NF;i++) if($i=="from") print $(i+1)}'

Extracting the IP address

'awk' iterates over each word in the line.

'sort' Sorting results

'uniq -c' Counting repetitions

'sort -nr' Sort by number

The result indicates that the IP address 192.168.150.128 made 304 failed login attempts.

sudo grep -a "Accepted password" /var/log/auth.log | awk '{for(i=1;i<=NF;i++) if($i=="from") print $(i+1)}' | sort | uniq -c | sort -nr

This command is the counterpart to the previous one, but it counts successful login attempts instead of failed ones.

The results indicate that the IP address 192.168.150.128 successfully logged in twice.
