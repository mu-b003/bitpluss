What Is Command and Control?

What Is Command and Control?

Command and Control, commonly called C2, refers to the communication channel an attacker uses to interact with compromised systems.

After a system is compromised, an attacker may use C2 communication to send instructions, receive information, maintain access, or perform additional actions on the affected system.

How Does C2 Communication Work?

A compromised device may communicate with infrastructure controlled by an attacker. The communication can use different network protocols and may attempt to blend into normal network traffic.

From a SOC perspective, the important question is whether the communication is expected for that system and application.

Common C2 Indicators

Repeated Outbound Connections: A device repeatedly connecting to the same unusual destination may require investigation.

Unfamiliar Domains: Unexpected DNS queries or connections to unfamiliar domains can provide useful clues.

Unusual Destinations: Connections to external IP addresses that are not normally used by the organization may require additional investigation.

Regular Communication Patterns: Repeated connections occurring at similar intervals can sometimes be a useful behavioral indicator.

Unexpected Processes: A process making network connections that do not match its expected behavior may require investigation.

How SOC Analysts Detect C2 Activity

C2 detection often involves combining network and endpoint evidence.

Connection → Destination → DNS → Process → Timeline → Context

The analyst can examine the destination IP or domain, connection frequency, protocol, destination port, DNS activity, and the process responsible for the connection.

C2 and DNS Logs

DNS logs can provide useful evidence during a C2 investigation. A compromised system may repeatedly query a domain before establishing outbound connections.

Analysts can compare DNS activity with network connections and endpoint events to determine whether the communication is expected.

C2 and Endpoint Activity

Network activity becomes more useful when it can be connected to a process on the endpoint.

For example, if an unusual application repeatedly communicates with an unfamiliar external destination, the analyst can investigate the process, user, file path, execution time, and related events.

Simple C2 Investigation Example

Suppose a workstation repeatedly connects to an unfamiliar external IP address every few minutes.

The analyst can check whether the destination is expected, identify any related DNS queries, determine which process initiated the connection, and search other systems for similar activity.

If additional evidence indicates that the communication is associated with suspicious software or known malicious infrastructure, the investigation can be escalated according to the organization's incident response process.

C2 and MITRE ATT&CK

Command and Control is also represented as a tactic in the MITRE ATT&CK framework.

ATT&CK documents different techniques that adversaries may use to communicate with compromised systems. SOC analysts can use this information to understand behaviors and develop or investigate relevant detections.

C2 Detection Challenges

Detecting C2 is not always simple because legitimate applications also communicate regularly with external services.

For this reason, analysts should not classify a connection as malicious based only on its destination or frequency. Process information, DNS activity, historical behavior, threat intelligence, and other evidence should be considered together.

Key Takeaway

Command and Control describes communication between a compromised system and attacker-controlled infrastructure.

For SOC analysts, detecting potential C2 activity involves examining network connections, DNS requests, processes, destinations, timing patterns, and related security events to determine whether the communication is legitimate or suspicious.
