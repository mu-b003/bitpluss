What Is Endpoint Detection and Response?

What Is Endpoint Detection and Response?

Endpoint Detection and Response, commonly called EDR, is a security technology used to monitor computers and other endpoints for suspicious or potentially malicious activity.

Endpoints can include laptops, desktops, servers, and other devices connected to an organization's environment.

Why Is EDR Important?

Endpoints are often involved in security incidents. An attacker may execute a process, create a file, modify an account, run a command, or establish a network connection after gaining access to a system.

EDR provides visibility into these activities and helps security teams detect and investigate suspicious behavior.

What Does EDR Monitor?

EDR can collect information about processes, files, user activity, network connections, command execution, system changes, and other endpoint events.

The exact information available depends on the EDR product and its configuration.

How Does EDR Work?

A typical EDR workflow can be understood as:

Collect → Monitor → Detect → Alert → Investigate → Respond

An endpoint agent collects relevant activity and sends security telemetry to the EDR platform. Detection mechanisms can then identify behavior that may require investigation.

When suspicious activity is detected, the security team can examine the available endpoint evidence and determine what happened.

EDR Alerts

EDR can generate alerts for different types of suspicious behavior, such as unusual process execution, malicious files, suspicious command activity, or unexpected network connections.

An alert is a starting point for investigation rather than automatic proof of compromise. Analysts need to examine the surrounding evidence and context.

How SOC Analysts Use EDR

SOC analysts can use EDR to investigate which user and device were involved, what process started the activity, which files were created or modified, and what network connections occurred.

They can also correlate endpoint evidence with authentication, DNS, firewall, and SIEM data.

EDR Investigation Example

Imagine an EDR alert reports suspicious PowerShell activity on a workstation.

The analyst can investigate the user, process tree, command-line information, timestamp, parent process, files involved, and network connections.

The analyst can then correlate this information with other logs to determine whether the activity was expected or potentially malicious.

EDR and Incident Response

EDR can support incident response by providing detailed endpoint evidence and, depending on the product, response capabilities.

Security teams may be able to isolate an affected endpoint, stop a malicious process, quarantine a file, or take other response actions according to their procedures.

EDR vs SIEM

EDR focuses primarily on endpoint activity, while a SIEM provides centralized collection and analysis of security events from many different sources.

They can work together. For example, a SIEM alert may identify suspicious activity, while EDR provides detailed information about the process and files involved on the affected endpoint.

Key Takeaway

EDR provides visibility into endpoint activity and helps security teams detect and investigate suspicious behavior.

For SOC analysts, understanding EDR is important because endpoint evidence can explain what happened on a system and can be correlated with network, authentication, and other security logs during an investigation.
