Headers (HTTP headers)

The headers contain a lot of information that helps you with Recon, and they also contain security settings that, if missing, create vulnerabilities.

Important Security Headers:

Content-Security-Policy (CSP)

It controls which sources you can download scripts/images/styles from. The strongest defense against XSS.

Content-Security-Policy: default-src 'self'; script-src 'self' cdn.example.com

If missing = the site is more exposed to XSS attacks.

X-Frame-Options

Embedding the site with an iframe from another site is prohibited. If it's missing, it's vulnerable to clickjacking (making the user click a button when they think it's doing something else).

X-Frame-Options: DENY

Strict-Transport-Security (HSTS)

The browser is forced to communicate only via HTTPS for a certain period, even if you manually type http://.

Strict-Transport-Security: max-age=31536000; includeSubDomains

X-Content-Type-Options: nosniff

It prevents the browser from "guessing" the file type — protecting against certain file-loading attacks.

Headers reveal information (that is dangerous to them):

Server: Apache/2.4.29 (Ubuntu) X-Powered-By: PHP/7.2.1

This gives you the server version and the technology used → You can then search for known vulnerabilities (CVEs) specific to that version. Professional reports recommend hiding them.

A practical tool:

A website securityheaders.com that checks any domain and gives you a rating (A to F) based on the headers present — excellent for quick training.
