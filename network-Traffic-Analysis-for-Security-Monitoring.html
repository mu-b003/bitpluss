What Is Network Traffic Analysis?

What Is Network Traffic Analysis?

Network traffic analysis is the process of examining network communications to understand what systems are communicating, what protocols are being used, and whether the activity appears normal or suspicious.

For SOC analysts, network traffic provides important evidence when investigating security alerts, suspicious connections, malware activity, and potential attacks.

What Can Network Traffic Show?

Network traffic can provide information about the source and destination of a connection, ports, protocols, timestamps, data flows, and other communication details.

Depending on the available monitoring tools, analysts may also be able to examine DNS requests, HTTP activity, TLS connections, and other network metadata.

Important Network Traffic Fields

Source IP: The system initiating the communication.

Destination IP: The system receiving the communication.

Source and Destination Ports: Ports help identify the services or applications involved in a connection.

Protocol: Common protocols include TCP, UDP, DNS, HTTP, HTTPS, and SSH.

Timestamp: Helps establish when communication occurred and build an investigation timeline.

Direction: Shows whether traffic is entering or leaving a system, which can be useful when investigating unusual outbound connections.

Normal vs Suspicious Traffic

Not every unusual connection is malicious. Security analysts need to understand what normal network behavior looks like before identifying anomalies.

Potentially suspicious patterns may include unexpected external connections, repeated connections to an unfamiliar destination, unusual ports, large unexpected data transfers, or communication that does not match the normal behavior of the system.

Common Network Patterns Analysts Investigate

Port Scanning: A system attempting connections to many ports or hosts may indicate scanning activity.

Repeated Connections: Regular connections to the same external destination may require investigation, especially when they are unexpected.

Unusual DNS Requests: Unexpected domains or unusual DNS behavior can provide useful evidence during an investigation.

Unexpected Outbound Traffic: A system communicating with an unfamiliar external service may require additional investigation.

How SOC Analysts Analyze Network Traffic

A basic investigation can follow this process:

Source → Destination → Protocol → Port → Time → Pattern → Context

The analyst first identifies the systems involved and then examines the protocol, ports, timestamps, and frequency of communication.

Additional context can come from DNS logs, firewall logs, endpoint events, authentication logs, threat intelligence, or packet captures.

Network Traffic and Wireshark

Wireshark is a network protocol analyzer that can be used to inspect captured network packets.

An analyst can examine packet details such as Ethernet frames, IP addresses, TCP or UDP information, ports, DNS queries, and other protocol fields.

Packet analysis can provide deeper evidence when log information alone is not enough to understand a network event.

Example Investigation

Imagine an endpoint generates an alert because it repeatedly connects to an unfamiliar external IP address.

The analyst can examine the destination, connection frequency, destination port, DNS activity, the process responsible for the connection, and whether other systems contacted the same destination.

Combining these sources can help determine whether the connection is expected, suspicious, or requires further investigation.

Why Network Traffic Matters in a SOC

Network monitoring provides visibility into communication between systems. It can help analysts detect suspicious connections, investigate alerts, understand attack activity, and build timelines during incidents.

Network evidence becomes even more useful when correlated with endpoint, authentication, DNS, and other security logs.

Key Takeaway

Network traffic analysis helps SOC analysts understand how systems communicate and identify patterns that may require investigation.

The goal is not to treat every unusual connection as an attack. Analysts should examine the communication pattern, compare it with expected behavior, and correlate network evidence with other security information.
