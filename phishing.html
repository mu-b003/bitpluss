What Is Phishing?

What Is Phishing?

Phishing is a social engineering technique in which an attacker attempts to trick a person into revealing information, opening a malicious file, clicking a harmful link, or performing another action that benefits the attacker.

Phishing commonly uses email, but similar attacks can also occur through text messages, messaging platforms, social media, and other communication channels.

How Does Phishing Work?

A typical phishing attack creates a message that appears to come from a trusted person or organization.

The message may create urgency, request a password reset, ask the user to review an account, or direct them to a website or attachment.

The goal is to persuade the recipient to take an action without carefully checking whether the request is legitimate.

Common Phishing Indicators

Suspicious Sender: The sender address may use an unfamiliar domain or contain small differences from a legitimate address.

Unexpected Links: A message may contain a link that does not match the organization it claims to represent.

Urgent Requests: Messages may pressure users to act quickly by claiming that an account will be disabled or that an immediate action is required.

Unexpected Attachments: An attachment that was not expected by the recipient may require investigation, especially when it requests the user to enable or execute something.

Unusual Language or Requests: Unexpected requests for credentials, payments, sensitive information, or account changes can be warning signs.

How SOC Analysts Investigate Phishing

A SOC analyst should examine the message and collect relevant evidence before deciding whether it is malicious.

Email → Sender → Headers → Links/Attachments → User Activity → Related Events → Finding

The analyst may examine the sender address, email headers, URLs, attachments, recipient information, timestamps, and related security alerts.

Investigating a Phishing Link

If an email contains a suspicious link, the analyst can examine the URL and determine where it leads without unnecessarily exposing users or systems to the destination.

The domain, URL structure, DNS activity, web logs, and available threat intelligence can provide additional context.

Investigating a Phishing Attachment

Attachments should be handled carefully during analysis. Security teams can use appropriate analysis environments and security tools to examine suspicious files.

Useful evidence may include the file name, hash, file type, origin, endpoint alerts, process activity, and network connections associated with the file.

What Happens If a User Clicks?

If a user interacts with a suspicious email, the investigation should not stop at the email itself.

The analyst may check authentication logs, DNS activity, web requests, endpoint processes, and other events around the time of the interaction.

This helps determine whether the interaction resulted in additional suspicious activity.

Phishing and Security Awareness

Technical controls can reduce phishing risk, but users are also an important part of the security process.

Security awareness helps users recognize suspicious messages and report them to the appropriate security team instead of interacting with them.

Key Takeaway

Phishing attempts to manipulate users into performing an action that can benefit an attacker. For SOC analysts, investigating phishing involves examining the message, sender, links, attachments, and related activity across security logs.

The most important part of a phishing investigation is connecting the email with other evidence to understand what happened before and after the user interaction.
