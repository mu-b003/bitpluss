SQL Injection (SQLi)

SQL Injection (SQLi) is a web vulnerability that allows an attacker to interfere with database queries.

It occurs when user input is included in SQL statements without proper validation or parameterization.

Why Is SQL Injection Dangerous?

An attacker may be able to:

• Read sensitive data

• Bypass authentication

• Modify database records

• Delete data

• Execute administrative operations

• Take control of the application

How SQL Injection Works

Consider the following login query:

SELECT * FROM users
WHERE username='admin'
AND password='password';

If user input is not properly handled, an attacker may alter the query logic.

Example of a Vulnerable Query

SELECT * FROM users
WHERE username='$username'
AND password='$password';

The application directly inserts user input into the SQL query.

Authentication Bypass

Input:

' OR '1'='1

The resulting query becomes:

SELECT * FROM users
WHERE username=''
OR '1'='1'
AND password='';

The condition is always true, which may bypass authentication.

Types of SQL Injection

In-Band SQL Injection

The attacker receives results through the same communication channel.

Error-Based SQL Injection

Database error messages reveal useful information.

Example:

You have an error in your SQL syntax
Union-Based SQL Injection

Uses the UNION operator to retrieve data from other tables.

Example:

' UNION SELECT null,null --
Blind SQL Injection

The application does not display database errors or query results.

The attacker infers information from application behavior.

Boolean-Based Blind SQLi

The response changes based on true or false conditions.

Example:

' AND 1=1 --
' AND 1=2 --
Time-Based Blind SQLi

The database delays its response when a condition is true.

Example:

' AND SLEEP(5) --

Common Injection Points

• Login forms

• Search functionality

• URL parameters

• Cookies

• HTTP Headers

• API parameters

Example Vulnerable URL

https://example.com/product?id=5

Testing:

https://example.com/product?id=5'

An error may indicate SQL Injection.

Database Enumeration

Attackers often attempt to discover:

• Database version

• Database name

• Table names

• Column names

Common SQLi Indicators

• SQL error messages

• Different application responses

• Unexpected login success

• Delayed responses

• Application crashes

SQL Injection and Authentication

A vulnerable login page may allow attackers to access accounts without valid credentials.

This is one of the most common SQL Injection scenarios.

Preventing SQL Injection

Parameterized Queries

Use prepared statements instead of building SQL queries with string concatenation.

Input Validation

Validate user input before processing it.

Least Privilege

Database accounts should have only the permissions they need.

Error Handling

Do not expose database errors to users.

What Should a Penetration Tester Check?

• URL parameters

• Form inputs

• Search fields

• Cookies

• JSON request bodies

• Hidden parameters

• HTTP headers

• Error messages

• Response timing differences

SQLi Testing Workflow

1- Identify user-controlled input.

2- Test for special characters.

3- Observe application responses.

4- Determine the SQL Injection type.

5- Verify exploitability.

6- Assess impact and affected data.
