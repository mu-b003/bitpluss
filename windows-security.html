Introduction — Windows and Cybersecurity

Windows is the most widely used operating system in the world — which also makes it the most targeted by attackers. Understanding how Windows works internally is essential for any cybersecurity professional, whether you are defending systems or testing them.

What You Will Learn

Windows architecture — User accounts and permissions — Active Directory — Registry — Event Logs — Common attacks — Hardening techniques — and essential security tools built into Windows.

Requirements

Basic familiarity with using Windows. No prior security experience needed.

Windows Architecture

How Windows is Structured

Windows is divided into two main zones: User Mode and Kernel Mode. Understanding this separation is fundamental to understanding privilege escalation attacks.

Kernel Mode

The core of the OS — has full access to hardware and memory. Runs: Windows Kernel (ntoskrnl.exe), Hardware Abstraction Layer (HAL), and Kernel-mode drivers. A crash here causes a Blue Screen of Death (BSOD).

User Mode

Where applications and services run — restricted access to hardware. Must request resources through system calls. Runs: Win32 subsystem, services, and user applications.

Key System Processes

smss.exe       — Session Manager — first user-mode process
csrss.exe      — Client/Server Runtime — manages Win32 console
winlogon.exe   — Handles login/logout and Ctrl+Alt+Delete
services.exe   — Service Control Manager — manages all services
lsass.exe      — Local Security Authority — handles authentication

Attackers often disguise malware as these processes — always check the full path. Legitimate processes live in C:\Windows\System32\

Windows Registry

A hierarchical database storing system and application configuration. Five root keys:

HKEY_LOCAL_MACHINE (HKLM)  — System-wide settings
HKEY_CURRENT_USER  (HKCU)  — Current user settings
HKEY_CLASSES_ROOT  (HKCR)  — File associations
HKEY_USERS         (HKU)   — All user profiles
HKEY_CURRENT_CONFIG (HKCC) — Hardware profile

Malware commonly uses Registry for persistence. Key autorun location: HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run

User Accounts and Permissions

Account Types

Administrator — Full control over the system. Can install software, modify system files, and manage other users.

Standard User — Limited permissions. Cannot install system-wide software or change system settings.

Guest — Minimal access. Disabled by default in modern Windows.

SYSTEM — The most privileged built-in account. Used by the OS itself. More powerful than Administrator.

UAC — User Account Control

A security feature that prompts for confirmation before allowing privileged actions — even for Administrators. Prevents malware from silently escalating privileges.

UAC Levels:
Always notify          — Highest security
Notify app changes     — Default setting
Notify app changes (no dimming)
Never notify           — Disabled — dangerous!

NTFS Permissions

Every file and folder on NTFS has an Access Control List (ACL) defining who can do what.

Full Control   — Read, write, modify, delete, change permissions
Modify         — Read, write, modify, delete
Read & Execute — View and run files
Read           — View only
Write          — Create and modify only

Principle of Least Privilege

Always give users and processes the minimum permissions they need to do their job — nothing more. This limits the damage if an account is compromised.

Useful Commands

net user                        — List all local users
net user username /add          — Create a new user
net localgroup administrators   — List admin group members
whoami /priv                    — Show current user privileges
icacls C:\folder                — Show folder permissions
Active Directory

What is Active Directory?

Active Directory (AD) is Microsoft's directory service for managing users, computers, and resources in a network. Used in almost every corporate environment — making it a primary target for attackers.

Core Components

Domain — A logical grouping of network objects (users, computers, printers) sharing the same AD database.

Domain Controller (DC) — The server that runs Active Directory. Handles authentication and policy enforcement.

Organizational Unit (OU) — A container inside a domain for organizing objects and applying Group Policies.

Forest — The top-level container — a collection of one or more domains sharing a schema.

Authentication — Kerberos

Windows domains use Kerberos for authentication. The process uses tickets instead of passwords over the network:

1. User logs in → sends credentials to the KDC (Key Distribution Center)
2. KDC issues a TGT (Ticket Granting Ticket)
3. User presents TGT to request a Service Ticket
4. Service Ticket is presented to the target service
5. Access granted — password never sent over the network

Common AD Attacks

Pass-the-Hash — Attacker uses a stolen NTLM hash to authenticate without knowing the plaintext password.

Kerberoasting — Attacker requests service tickets and cracks them offline to get service account passwords.

Golden Ticket — Attacker forges a TGT using the KRBTGT hash — gives unlimited domain access.

DCSync — Attacker mimics a Domain Controller to pull password hashes from AD.

Basic Defense

Use tiered administration — separate accounts for different privilege levels.

Enable Protected Users security group for privileged accounts.

Monitor for abnormal Kerberos ticket requests (Event ID 4769).

Regularly audit AD group memberships.

Windows Firewall and Network Security

Windows Defender Firewall

Built-in stateful firewall that filters inbound and outbound traffic based on rules. Supports three profiles:

Domain Profile   — When connected to a corporate domain network
Private Profile  — Home or trusted network
Public Profile   — Untrusted networks (coffee shops, airports)

Managing Firewall via CMD

— Check firewall status
netsh advfirewall show allprofiles

— Block an inbound port
netsh advfirewall firewall add rule name="Block Port 23" ^
      dir=in action=block protocol=TCP localport=23

— Allow an application
netsh advfirewall firewall add rule name="Allow MyApp" ^
      dir=in action=allow program="C:\MyApp\app.exe"

— Reset all rules to default
netsh advfirewall reset

Dangerous Open Ports to Watch

445   — SMB  — targeted by WannaCry and EternalBlue
3389  — RDP  — Remote Desktop — common brute-force target
23    — Telnet — unencrypted — disable immediately
21    — FTP  — unencrypted — replace with SFTP
135   — RPC  — often exploited in older Windows

NetStat — Check Active Connections

netstat -ano              — All connections with PID
netstat -ano | find "LISTENING"   — Open ports only
netstat -ano | find ":4444"       — Check a specific port
Windows Event Logs

What are Event Logs?

Windows records system activity in Event Logs — essential for detecting attacks and investigating incidents. Accessed via Event Viewer (eventvwr.msc).

Main Log Categories

Application — Events from applications and programs.

Security — Login attempts, privilege use, object access. Most important for security.

System — Events from Windows system components and drivers.

PowerShell/Microsoft-Windows-PowerShell — PowerShell command execution — critical for detecting attacks.

Critical Security Event IDs

4624  — Successful login
4625  — Failed login attempt
4634  — Account logged off
4648  — Login using explicit credentials (RunAs)
4672  — Special privileges assigned to new login
4688  — New process created (process tracking)
4698  — Scheduled task created
4720  — User account created
4732  — User added to a security group
4771  — Kerberos pre-authentication failed
7045  — New service installed

Querying Logs via PowerShell

# Find all failed logins
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625} |
    Select-Object TimeCreated, Message | Format-List

# Find new processes in the last hour
Get-WinEvent -FilterHashtable @{
    LogName='Security'; Id=4688;
    StartTime=(Get-Date).AddHours(-1)
}

Golden Rules

Enable audit policies — many events are off by default.

Forward logs to a centralized SIEM (Splunk, ELK, Wazuh).

Set log size large enough to retain history — attackers clear logs after intrusion.

Common Windows Attacks

Pass-the-Hash (PtH)

The attacker captures an NTLM hash from memory (using Mimikatz) and uses it directly to authenticate — without cracking the password.

Defense:
 Enable Protected Users group
 Disable NTLM where possible — enforce Kerberos
 Use Credential Guard (Windows 10/11 Enterprise)

Mimikatz

A famous post-exploitation tool that extracts plaintext passwords, hashes, and Kerberos tickets from Windows memory (LSASS process).

Defense:
 Enable LSA Protection: 
   reg add HKLM\SYSTEM\CurrentControlSet\Control\Lsa /v RunAsPPL /t REG_DWORD /d 1
 Enable Windows Defender Credential Guard
 Restrict local administrator accounts

Lateral Movement

After gaining initial access, the attacker moves to other machines using tools like PsExec, WMI, or SMB with stolen credentials.

Defense:
 Use unique local admin passwords on every machine (LAPS)
 Restrict SMB and RPC access between workstations
 Monitor Event ID 4688 for suspicious process creation

Persistence Techniques

Attackers use these common methods to survive reboots:

Registry Run Keys   — HKLM\...\CurrentVersion\Run
Scheduled Tasks     — schtasks /create
Services            — sc create
Startup Folder      — C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup
WMI Subscriptions   — Triggered on system events

Living off the Land (LOL)

Attackers use built-in Windows tools to avoid detection — no malware needed.

PowerShell  — Download and execute payloads
WMI         — Remote execution and persistence
CertUtil    — Download files from the internet
Regsvr32    — Execute remote scripts
Mshta       — Run HTML applications
Rundll32    — Execute DLL payloads
Windows Hardening

What is Hardening?

Reducing the attack surface of a Windows system by disabling unnecessary features, applying secure settings, and enforcing security policies.

Essential Hardening Steps

1. Keep Windows Updated — Enable Windows Update and apply patches immediately. Most attacks exploit known vulnerabilities.

2. Disable Unnecessary Services

# List running services
Get-Service | Where-Object {$_.Status -eq "Running"}

# Disable a service
Set-Service -Name "Telnet" -StartupType Disabled

3. Disable SMBv1 — The protocol exploited by WannaCry.

Set-SmbServerConfiguration -EnableSMB1Protocol $false -Force

4. Enable Windows Defender and all protection features.

Set-MpPreference -DisableRealtimeMonitoring $false
Set-MpPreference -EnableControlledFolderAccess Enabled

5. Disable RDP if not needed — or restrict it to specific IPs.

# Disable RDP
Set-ItemProperty -Path 'HKLM:\System\CurrentControlSet\Control\Terminal Server' `
                 -Name "fDenyTSConnections" -Value 1

6. Enable Audit Policies

auditpol /set /category:"Logon/Logoff" /success:enable /failure:enable
auditpol /set /category:"Account Logon" /success:enable /failure:enable
auditpol /set /category:"Process Creation" /success:enable

7. Use AppLocker or Windows Defender Application Control to whitelist allowed applications.

CIS Benchmarks

The Center for Internet Security publishes free hardening guides for every Windows version. Follow the CIS Benchmark for your OS version as a baseline.

PowerShell for Security

Why PowerShell?

PowerShell is the most powerful built-in tool for Windows administration and security — used by both defenders and attackers. Knowing it is essential.

Useful Security Commands

# List all local users
Get-LocalUser

# List all local groups
Get-LocalGroup

# Show members of Administrators group
Get-LocalGroupMember -Group "Administrators"

# List running processes with their paths
Get-Process | Select-Object Name, Id, Path | Format-Table

# Find recently modified files
Get-ChildItem C:\ -Recurse -ErrorAction SilentlyContinue |
    Where-Object { $_.LastWriteTime -gt (Get-Date).AddDays(-1) }

# Check scheduled tasks
Get-ScheduledTask | Where-Object {$_.State -ne "Disabled"}

# List installed services and their binary paths
Get-WmiObject Win32_Service | Select-Object Name, PathName, StartMode

PowerShell Logging — Detect Attacks

# Enable Script Block Logging via Registry
reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" ^
        /v EnableScriptBlockLogging /t REG_DWORD /d 1 /f

# View PowerShell logs
Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational" |
    Select-Object TimeCreated, Message | Format-List

Execution Policy

Restricted       — No scripts allowed (default)
RemoteSigned     — Local scripts OK, remote must be signed
AllSigned        — All scripts must be signed
Unrestricted     — All scripts run — dangerous!
Bypass           — Nothing is blocked — used by attackers

# Check current policy
Get-ExecutionPolicy

# Set policy
Set-ExecutionPolicy RemoteSigned -Scope LocalMachine
Windows Defender and Built-in Security Tools

Windows Defender Antivirus

Built-in real-time protection against malware. In Windows 10/11 it is a full enterprise-grade AV — keep it enabled.

# Run a quick scan
Start-MpScan -ScanType QuickScan

# Run a full scan
Start-MpScan -ScanType FullScan

# Update signatures
Update-MpSignature

# Check protection status
Get-MpComputerStatus

Windows Defender Firewall with Advanced Security

The full firewall management console — accessed via wf.msc. Supports inbound/outbound rules, connection security rules, and monitoring.

Credential Guard

Uses virtualization to isolate LSASS — prevents Mimikatz from extracting credentials. Available on Windows 10/11 Enterprise and Windows Server 2016+.

Secure Boot

A UEFI feature that verifies the bootloader signature before loading Windows — prevents bootkits and rootkits from loading before the OS.

BitLocker

Full disk encryption built into Windows Pro and Enterprise. Encrypts the entire drive — protects data if the physical device is stolen.

# Check BitLocker status
manage-bde -status

# Enable BitLocker
Enable-BitLocker -MountPoint "C:" -RecoveryPasswordProtector

Sysinternals Suite

Microsoft's free toolkit — essential for security analysis and incident response.

Process Explorer  — Advanced Task Manager — shows parent processes and DLLs
Autoruns          — Shows every program that runs at startup
TCPView           — Real-time network connections per process
Process Monitor   — Logs all file system, registry, and network activity
PsExec            — Remote command execution
Strings           — Extract readable strings from binary files
Security Checklist — Windows Hardening

Before Deploying Any Windows System

Windows Update is enabled and all patches applied

SMBv1 is disabled

RDP is disabled or restricted to specific IPs with NLA enabled

Windows Defender Antivirus and Firewall are enabled

UAC is set to default or higher — never disabled

All unnecessary services are disabled

Audit policies are enabled for Logon, Account Logon, and Process Creation

Event log sizes are configured to retain adequate history

Local Administrator account is renamed or disabled

LAPS is deployed to manage local admin passwords

PowerShell Script Block Logging is enabled

Credential Guard is enabled on supported hardware

BitLocker is enabled on all endpoints

LSA Protection (PPL) is enabled

Logs are forwarded to a centralized SIEM
