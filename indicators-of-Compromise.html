What Are Indicators of Compromise?

What Are Indicators of Compromise?

Indicators of Compromise, commonly called IoCs, are pieces of evidence that may indicate a system, account, or network has been involved in suspicious or malicious activity.

IoCs are commonly used by SOC analysts during alert investigation, incident response, threat hunting, and malware analysis.

Common Types of IoCs

IP Addresses: An IP address associated with suspicious or malicious network activity can be used as an indicator during an investigation.

Domain Names: Suspicious domains may be identified through DNS queries, web traffic, or threat intelligence sources.

File Hashes: A hash such as SHA-256 can be used to identify a specific file. Security teams can compare a suspicious file's hash with known threat intelligence.

File Names and Paths: Unusual files, locations, or executable names can provide additional evidence during an endpoint investigation.

Email Indicators: Sender addresses, malicious links, attachments, and other email characteristics can help identify phishing activity.

URLs: Suspicious URLs found in emails, browser activity, or network logs can be investigated as potential indicators.

IoCs in Security Logs

IoCs can appear in many different types of logs. For example, a suspicious IP address may appear in firewall or network logs, while a suspicious domain may appear in DNS logs.

A file hash or process name may be found in endpoint security logs, while a suspicious URL may appear in web proxy or HTTP logs.

How SOC Analysts Use IoCs

When an IoC is identified, analysts can search across available security data to determine whether the same indicator appears elsewhere.

For example, if a suspicious IP address is found in one alert, the analyst can search historical network logs to determine whether other systems communicated with that address.

This can help identify related activity and determine the possible scope of an investigation.

IoCs and Threat Intelligence

Threat intelligence sources can provide information about indicators associated with known malicious activity.

An analyst may compare an IP address, domain, URL, or file hash found during an investigation with available threat intelligence. However, an indicator should not be treated as proof of malicious activity without considering its context and reliability.

IoC Example

Imagine a user visits a suspicious website and the endpoint later makes a connection to an unusual external IP address.

The analyst can investigate the DNS request, destination IP, process responsible for the connection, timestamps, and other related events.

If the same destination appears on multiple systems or is associated with known malicious activity, it can provide additional evidence for the investigation.

IoCs vs Normal Activity

Not every suspicious-looking indicator is malicious. IP addresses can be shared, domains can change ownership, and legitimate software can communicate with external services.

For this reason, analysts should combine IoCs with other evidence such as user activity, process information, network connections, and timelines.

IoCs and Incident Response

IoCs can also help incident response teams search for affected systems and determine whether an identified threat exists elsewhere in the environment.

After an incident, the identified indicators can be used to search historical logs and check whether similar activity occurred before the original alert.

Key Takeaway

Indicators of Compromise provide useful evidence during security investigations. Common IoCs include IP addresses, domains, URLs, file hashes, filenames, and suspicious email characteristics.

The important part of working with IoCs is not simply finding a matching indicator. Analysts need to examine its context, connect it with other events, and determine what the evidence shows.
