Cookies

Cookies are small pieces of data stored by the browser and sent to the server with future requests.

They are commonly used to maintain user sessions, store preferences, and track user activity.

How Cookies Work

1- The server sends a cookie to the browser.

Set-Cookie: session=abc123

2- The browser stores the cookie.

3- The browser automatically includes the cookie in future requests.

Cookie: session=abc123

Why Are Cookies Used?

• User Authentication

• Session Management

• User Preferences

• Analytics and Tracking

Cookie Structure

Set-Cookie: session=abc123

Explanation:

session  → Cookie Name
abc123   → Cookie Value

Cookie Attributes

Expires

Defines when the cookie will expire.

Set-Cookie: session=abc123; Expires=Wed, 31 Dec 2026 23:59:59 GMT
Max-Age

Defines the lifetime of the cookie in seconds.

Set-Cookie: session=abc123; Max-Age=3600
Domain

Specifies which domain can access the cookie.

Set-Cookie: session=abc123; Domain=example.com
Path

Limits the cookie to a specific path.

Set-Cookie: session=abc123; Path=/admin
Secure

The cookie is only sent over HTTPS connections.

Set-Cookie: session=abc123; Secure
HttpOnly

Prevents JavaScript from accessing the cookie.

Helps reduce the risk of cookie theft through XSS attacks.

Set-Cookie: session=abc123; HttpOnly
SameSite

Controls whether the cookie is sent with cross-site requests.

Set-Cookie: session=abc123; SameSite=Strict

Possible values:

• Strict

• Lax

• None

Session Cookies vs Persistent Cookies

Session Cookies

Exist only while the browser is open.

Deleted when the browser is closed.

Persistent Cookies

Remain stored until their expiration date.

Used for "Remember Me" functionality.

Example Authentication Flow

User logs in:

POST /login

Server response:

Set-Cookie: session=abc123; HttpOnly; Secure

Future requests:

GET /profile
Cookie: session=abc123

Cookies and Security

Cookies often contain session identifiers.

If an attacker steals a valid session cookie, they may be able to impersonate the user.

Common Cookie Attacks

Session Hijacking

Stealing a user's session cookie to gain unauthorized access.

Session Fixation

Forcing a victim to use a known session ID.

Cross-Site Scripting (XSS)

JavaScript can steal cookies that are not protected with HttpOnly.

Cross-Site Request Forgery (CSRF)

Abuses automatically sent cookies to perform actions on behalf of the victim.

What Should a Penetration Tester Check?

• Are session cookies predictable?

• Is the Secure flag enabled?

• Is the HttpOnly flag enabled?

• Is SameSite configured correctly?

• Are sensitive values stored inside cookies?

• Can cookies be modified by the user?

• Are session IDs rotated after login?

Example Cookie Header

Cookie: session=abc123;
role=user;
theme=dark
