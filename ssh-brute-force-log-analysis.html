brute-force Detection

For this practical task we will capture a brute-force attack We will follow a scenario to generate the attack and then analyze it Have you set up the labs If not you can do so via this link.

The `ip a` command is the first one we use to find the victim's IP address, as we will need it later when launching the attack. and the Victim (ubuntu) ip is 192.168.150.129

The command `sudo systemctl status ssh` is used to check the status of the SSH server service as you can see from the results it is running.

We have obtained the information we needed—specifically the victim's IP address and the status of the SSH service Now that we have what we need the next step is to execute the attack the goal is to generate log entries within the log file.

Go to the Kali machine the preparations for the attack begin here Use the command `touch passwords.txt` to create an empty file, then use the command `nano passwords.txt` to open the file and enter the passwords.

Enter password you can type whatever you like provided they are all incorrect so that you do not succeed in logging in later.

mustang6667, mustang65ch1do, mustang6561, mustang654, mustang652, mustang645

'hydra -l developer -P passwords.txt ssh://192.168.150.129' this is the step where the attack is executed using the Hydra tool.

'hydra' The command to run the Hydra tool.

'-l developer' The username used for testing

'-P passwords.txt' Password file name

'ssh://192.168.150.129' Targeting the SSH service on the device with the address 192.168.150.129

Thus we have generated the required number of records in the authentication records file In the next step we will begin the analysis process as SOC analysts.

The results indicate that the Hydra tool failed to log in And this is exactly what we need.

With this in mind think like an SOC analyst performing an analysis.

'sudo grep "Faile password" /var/log/auth.log | awk '{print $1, $2, $3, $(NF-3)}'

The `sudo` command runs a command with administrator privileges

This command aims to retrieve the timestamps of failed login attempts along with the originating IP addresses.

The `sudo` command runs a command with administrator privileges.

The `grep "Failed password"` command searches for lines containing the phrase Failed password

'/var/log/auth.log' The authentication log file that records SSH and sudo events

'awk' to select specific fields

'$1' Date and Time

'$2' Device Name

'$3' Program or process name: sshd-session[...]

'$(NF-3)'The third field from the end

Based on the results we conclude that all failed login attempts originated from a single IP address within a very short timeframe indicating a brute-force attack pattern.

The command `sudo grep "Failed password" /var/log/auth.log` displays all failed login attempts to the SSH server.

This project demonstrated how SSH brute-force attempts can be generated in a controlled lab environment and analyzed using Linux authentication logs. By reviewing failed login events, identifying the source IP, and interpreting SSH log entries, the activity followed a basic SOC Level 1 investigation workflow.
