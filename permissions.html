Linux Permissions

Linux permissions are used to control who can access files and directories and what actions they can perform.

Every file and directory has permissions assigned to the owner, group, and others.

Why Are Permissions Important?

Permissions help protect files from unauthorized access and modification.

They are a fundamental part of Linux security.

Permission Structure

Example:

-rwxr-xr--

Breakdown:

- rwx r-x r--
  |   |   |
  |   |   └── Others
  |   └────── Group
  └────────── Owner

Permission Types

Read (r)

Allows viewing the contents of a file.

For directories, allows listing files.

r = 4
Write (w)

Allows modifying a file.

For directories, allows creating and deleting files.

w = 2
Execute (x)

Allows executing a file as a program.

For directories, allows entering the directory.

x = 1

Permission Groups

Owner (u)

The user who owns the file.

Group (g)

Users belonging to the assigned group.

Others (o)

All other users on the system.

Viewing Permissions

ls -l

Example output:

-rwxr-xr-- 1 user users 1024 notes.txt

Meaning:

Owner  = rwx
Group  = r-x
Others = r--

Numeric Permissions

Linux permissions can be represented using numbers.

r = 4
w = 2
x = 1

Examples:

7 = rwx = 4+2+1
6 = rw- = 4+2
5 = r-x = 4+1
4 = r-- = 4

Common Permission Values

777 = rwxrwxrwx
755 = rwxr-xr-x
744 = rwxr--r--
700 = rwx------
644 = rw-r--r--
600 = rw-------

Changing Permissions

chmod

Used to modify file permissions.

Example:

chmod 755 script.sh

Result:

Owner  = rwx
Group  = r-x
Others = r-x

Symbolic Mode

Add execute permission:

chmod +x script.sh

Remove write permission:

chmod -w file.txt

Give owner full permissions:

chmod u+rwx file.txt

Changing Ownership

chown

Changes file ownership.

chown user file.txt

Change owner and group:

chown user:developers file.txt
chgrp

Changes group ownership.

chgrp developers file.txt

Directory Permissions

Directory permissions behave differently from file permissions.

r = List files
w = Create/Delete files
x = Enter directory

Special Permissions

SUID (Set User ID)

Allows a file to run with the permissions of its owner.

Example:

-rwsr-xr-x

Find SUID files:

find / -perm -4000 2>/dev/null
SGID (Set Group ID)

Allows execution with group permissions.

-rwxr-sr-x
Sticky Bit

Only the file owner can delete files inside the directory.

Common example:

/tmp
drwxrwxrwt

Permission Examples

Private file:

chmod 600 secrets.txt

Public script:

chmod 755 script.sh

Private directory:

chmod 700 projects

What Should a Penetration Tester Check?

• World-writable files

• Weak file permissions

• Sensitive files readable by everyone

• Misconfigured SUID binaries

• Misconfigured SGID binaries

• Writable system directories

• Privilege escalation opportunities

Useful Commands

ls -l
chmod
chown
chgrp
find / -perm -4000
find / -perm -2000
stat file.txt

Common Permission Values to Remember

777 → Everyone can do everything
755 → Common for scripts and directories
644 → Common for files
700 → Private directories
600 → Sensitive files
