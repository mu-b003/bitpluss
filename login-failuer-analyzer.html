Login Failuer Analyzer

This is a task that can be practically implemented in this task I will explain the analysis of failed login attempts I first generate a simulated attack within a virtual lab to create system logs then I analyze these logs to extract important information such as IP addresses number of failed attempts and timing with the aim of understanding how brute force attacks are detected from a SOC analyst's perspective.

The first command to update the system is `sudo apt update`

The command `sudo apt install openssh-server` is used to install the OpenSSH server.

The command `sudo systemctl status ssh` is used to check the status of the SSH service.

After confirming that the SSH service is stopped use the `sudo systemctl start ssh` command to start it then run the command again to verify that it is running.

Run the command `ip a` to find the victim's IP address, as we will need it later when executing the attack. and this is the ip of the victim '192.168.150.129'

The command `sudo tail -f /var/log/auth.log` is used to monitor and display authentication logs in real time.

The command `sudo adduser developer` is used to create a user named "developer"; we create this user because we intend to use it later during the attack process.

Enter a password you can remember later.

Run `sudo adduser IT-support` to create a user named "IT-support" and set a password you can remember repeat this process to create the other user.

We have finished preparing what we want to test in the next step we will launch the attack.

In this step go to your other machine such as Kali or the attacker's machine to carry out the first test.

We use the command `sudo developer@192.168.150.129` to connect to or access the user account on the victim's machine.

Enter an incorrect password three times to generate failed login records in the log file on ubuntu

Do the same thing as well.

We want to generate larger logs, so we will use the Hydra tool to do that.

We use the `touch passwords.txt` command to create the password file or dictionary.

'nano passwords.txt' To open the file and enter passwords, you can type whatever passwords you wish—provided they are incorrect and not the actual password of the user you are attempting to attack.

After entering the passwords press Ctrl+O to save then Enter and finally Ctrl+X to exit.

hydra -l admin -P passwords.txt ssh://192.168.150.129

Here we are executing a brute force attack using Hydra. Note that the username used is "admin" different from the "asmin" account we created but this is not an issue we can use it to analyze the attack against a non-existent user.

From here we stop. We have generated what we wanted. In the next step we will begin the analysis where we will represent the SOC analyst.

Imagine yourself as an SOC analyst right now.

The command `sudo grep "Failed password" /var/log/auth.log` is used to extract failed login attempts from the `auth.log` file. The results show three failed login attempts for the user "developer" from the IP address 192.168.150.128.

(Failed password for invalid user admin) It also became apparent that there were attempts to log in as a non-existent user indicating that the attacker does not know the specific usernames.

'sudo grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr'

This is intended to count the number of failed login attempts for each IP address.

( sudo grep "Failed password" /var/log/auth.log ) Extracting failed login attempts

( awk '{print $(NF-3)}' )Extracting the IP address

( 'sort' ) Arranging the headings

( 'uniq -c' ) Number of repetitions

( 'sort -nr' ) Sort by number

The result shows that an attacker with the IP address 192.168.150.128 made 19 failed login attempts.

'sudo grep -c "Failed password" /var/log/auth.log' Count all lines containing "Failed password".

'grep' searches for text within a file.

'-c' does not display the lines it only displays the count.

"Failed password" the text to search for.

'var/log/auth.log' Authentication logs file

'sudo grep "Failed password" /var/log/auth.log | head -1' View first attempt
