Kerberos

Kerberos is the default authentication protocol used in Active Directory environments.

It provides secure authentication by using tickets instead of transmitting passwords across the network.

Why Is Kerberos Important?

Kerberos is used by most Windows enterprise networks.

Understanding Kerberos is essential for Active Directory administration and penetration testing.

Goals of Kerberos

• Secure Authentication

• Single Sign-On (SSO)

• Mutual Authentication

• Reduced Password Exposure

Key Components

Client

The user or device requesting access to a service.

Service

The resource the user wants to access.

Examples:

• File Server

• Web Server

• Database Server

Key Distribution Center (KDC)

The trusted authority responsible for issuing Kerberos tickets.

In Active Directory, the Domain Controller acts as the KDC.

KDC Components

Authentication Server (AS)

Verifies user credentials.

Ticket Granting Server (TGS)

Issues service tickets.

Kerberos Authentication Flow

1- User enters credentials.

2- Client sends a request to the Authentication Server (AS).

3- The AS validates the user.

4- The AS issues a Ticket Granting Ticket (TGT).

5- The client requests access to a service from the TGS.

6- The TGS issues a Service Ticket.

7- The client presents the Service Ticket to the target service.

8- Access is granted.

Ticket Granting Ticket (TGT)

A TGT proves that a user has successfully authenticated.

The TGT is used to request service tickets without re-entering credentials.

Service Ticket (TGS Ticket)

A Service Ticket allows access to a specific service.

Examples:

CIFS/FileServer
HTTP/WebServer
MSSQL/DatabaseServer

Single Sign-On (SSO)

After obtaining a TGT, users can access multiple services without entering credentials again.

This is known as Single Sign-On.

Kerberos Ports

TCP 88
UDP 88

Kerberos Terminology

Principal

An identity in Kerberos.

Examples:

user@DOMAIN.LOCAL
server$@DOMAIN.LOCAL
Realm

The administrative boundary of a Kerberos environment.

In Active Directory, the realm is usually the domain name.

Example:

COMPANY.LOCAL
SPN (Service Principal Name)

A unique identifier for a service account.

Examples:

HTTP/web.company.local

MSSQLSvc/db.company.local

CIFS/fileserver.company.local

Benefits of Kerberos

• Strong authentication

• Mutual authentication

• Passwords are not transmitted across the network

• Supports Single Sign-On

• Widely used in Active Directory

Common Kerberos Attacks

Kerberoasting

Attackers request service tickets associated with service accounts.

The tickets can be cracked offline to recover passwords.

AS-REP Roasting

Targets accounts that do not require Kerberos pre-authentication.

Authentication data can be cracked offline.

Pass-the-Ticket (PtT)

Uses stolen Kerberos tickets to access services without knowing passwords.

Golden Ticket

A forged TGT created using the krbtgt account hash.

Provides nearly unrestricted domain access.

Silver Ticket

A forged service ticket targeting a specific service.

Common Enumeration Commands

View Kerberos tickets:

klist

View current user:

whoami

View domain information:

set l

What Should a Penetration Tester Check?

• Service accounts with SPNs

• Accounts vulnerable to AS-REP Roasting

• Kerberos tickets stored in memory

• Delegation configurations

• Weak service account passwords

• Privileged accounts

• Kerberos-related attack paths

Important Active Directory Accounts

krbtgt

Special account used to sign and generate Kerberos tickets.

Compromise of this account may lead to Golden Ticket attacks.

Common Terms to Remember

KDC   = Key Distribution Center

AS    = Authentication Server

TGS   = Ticket Granting Server

TGT   = Ticket Granting Ticket

SPN   = Service Principal Name

SSO   = Single Sign-On

PtT   = Pass-the-Ticket

Important Note

Most modern Active Directory attacks revolve around Kerberos.

A strong understanding of Kerberos is required before learning Kerberoasting, AS-REP Roasting, Delegation Abuse, Golden Tickets, and Silver Tickets.
